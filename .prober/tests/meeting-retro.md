# 스터디 미팅 회고: 사용자 사이트 회고 탭 · 작성

대상: `core-front` 내 스터디룸 › 스터디 일정 「회고」 탭(`/my/joined/{id}/schedule/retro`) · 회고 작성(`…/retro/write`). 스테이지의 테스트 계정만 사용한다.
PRD: [ST-039](../../01-planning/stories/crew-write-meeting-retro/PRD.md) · [ST-040](../../01-planning/stories/navigator-view-meeting-retros/PRD.md). API: [meeting-retro](../../specs/meeting-retro/spec.md).

준비: 한 반에 크루 둘(A · B) · 네비게이터 · 담당 캡틴(반 명부에 없는 경우와 명부에 있는 경우 각각). 정규 회차 셋 — 기한이 지난 회차, 미팅이 끝나 기한 전인 회차, 아직 시작 전인 회차.
미팅 종료는 실제 종료 시각이 없으면 회차 시작 + 120분, 기한은 다음 정규 회차 시작(마지막 회차는 종료 + 7일)이다. 시각은 프로필 시간대로 보인다.
결과 · 캡처에 회고 본문이나 실제 회원 정보를 남기지 않는다.

| ID | 절차 | 기대 결과 |
|---|---|---|
| RETRO-01 | 크루 A 가 기한 전 회차를 아직 안 쓴 채 스터디 일정을 연다 | 「회고」 탭 글자 옆에 점. 일정 표에는 회고 열이 없음 |
| RETRO-02 | 크루 A 가 회고 탭을 연다 | 끝난 회차만 칩으로 보이고 가장 최근 회차가 선택됨. 시작 전 회차 · 킥오프는 없음. 「MM.DD HH:mm 약칭까지」 · 「회고 작성」 · 작성 권유 문구 |
| RETRO-03 | 회차 칩을 바꾼 뒤 새로고침 | 주소의 `?meeting=` 이 바뀌고 새로고침해도 그 회차에 머묾 |
| RETRO-04 | 「회고 작성」 → 좋았던 점 · 개선할 점을 비우거나 공백만 넣고 제출 | 칸마다 「…을 적어 주세요.」, 저장되지 않음. 고치면 그 칸 오류가 바로 사라짐 |
| RETRO-05 | 500자를 넘겨 붙여 넣기 | 500자에서 더 들어가지 않고 글자 수가 보임 |
| RETRO-06 | 작성 페이지 회차 정보 확인 | 회차 · 날짜(요일) · 기한 문구 · 「미팅 종료 MM.DD HH:mm 약칭」. 프로필 시간대를 바꾸면 날짜 · 시각 · 약칭이 함께 바뀜 |
| RETRO-07 | 필수 두 칸을 쓰고(소감 비움) 제출 | 「회고를 남겼어요.」 토스트 후 그 회차 회고 탭. 탭 옆 점 사라짐 · 버튼 「내 회고 수정」 · 권유 문구 사라짐. 문항별 목록에 내 답이 「나」 표시로 보이고 소감 카드에는 내 줄이 없음 |
| RETRO-08 | 「내 회고 수정」 → 내용 고쳐 「수정 저장」 | 쓴 내용이 채워진 폼, 제목 「n회차 회고 수정」. 「회고를 고쳤어요.」. 고치기 전에 받은 👍 수 유지 |
| RETRO-09 | 작성 중 탭 · 「취소」 · 다른 메뉴를 누른다 | 「저장하지 않은 변경이 있습니다」 확인 창. 머물기 · 나가기 모두 동작 |
| RETRO-10 | 크루 B 로 같은 회차를 연다 | 쓰기 전에도 A 의 답이 실명으로 보임. A 의 답 옆 👍 칩(0 도 표시) |
| RETRO-11 | B 가 A 의 좋았던 점 👍 → 다시 눌러 취소 → 새로고침 | 누르는 즉시 +1 · 누른 상태, 취소 즉시 −1. 새로고침해도 서버 값과 같음. 깜빡임 없음 |
| RETRO-12 | B 가 여러 답의 👍 를 빠르게 연달아 누른다 | 각 칸이 바로 바뀌고 응답 뒤에도 값이 튀지 않음. 같은 칸을 두 번 빠르게 누르면 첫 응답 전 두 번째는 무시 |
| RETRO-13 | 네트워크를 끊고 👍 | 오류 토스트 후 그 칸만 누르기 전으로 되돌아감 |
| RETRO-14 | A 가 내 답을 본다 | 내 답에는 누를 수 없는 받은 수만 보임 |
| RETRO-15 | 문항별 순서 확인 | 👍 많은 순, 같으면 먼저 쓴 순서 |
| RETRO-16 | 기한이 지난 회차를 고른다 | 「… 마감」 · 비활성 「회고 마감」. 👍 는 계속 누를 수 있음 |
| RETRO-17 | 기한 지난 회차 · 시작 전 회차의 `…/retro/write?meeting=` 을 주소로 직접 연다 | 「작성 기한이 지나 회고를 쓰거나 고칠 수 없어요.」 · 「미팅이 끝나면 회고를 쓸 수 있어요.」와 「회고 목록으로」 |
| RETRO-18 | 작성 페이지를 연 채 기한을 넘긴 뒤 제출 | 「작성 기한이 지나 저장하지 못했어요.」 · 페이지에 머묾 |
| RETRO-19 | 끝난 회차가 하나도 없는 반에서 회고 탭 | 「아직 끝난 미팅이 없어요. 미팅이 끝나면 여기서 회고를 남기고 볼 수 있어요.」 |
| RETRO-20 | 아무도 안 쓴 끝난 회차 | 「아직 이 회차에 남긴 회고가 없어요.」 |
| RETRO-21 | 크루로 회고 탭 | 「n명 중 m명 작성」 · 작성 현황 목록이 없음. 안 쓴 사람 이름이 어디에도 보이지 않음 |
| RETRO-22 | 네비게이터로 회고 탭 | 「n명 중 m명 작성」 · 작성 현황(쓴 사람 앞 「작성」, 안 쓴 사람 뒤 「미작성」, 내 줄 「(나)」). 본인 회고 작성 · 수정 가능 |
| RETRO-23 | 반 명부에 없는 담당 캡틴으로 회고 탭 · 작성 주소 직접 열기 | 작성 현황은 보이고 작성 버튼 · 탭 옆 점은 없음. 작성 주소를 열면 안내 없이 그 회차의 회고 탭으로 돌아감 |
| RETRO-24 | 회차 시작 전에 참여를 중단한 크루가 있는 회차 | n(쓸 사람)과 미작성 목록에 그 크루가 없음 |
| RETRO-25 | 모바일 폭에서 회고 탭 · 작성 페이지 | 회차 칩 · 기한 · 버튼이 줄바꿈되어 잘리지 않음. 답 줄의 이름 · 답 · 👍 가 겹치지 않음 |
| RETRO-26 | 반 명부에 있는 담당 캡틴으로 회고 탭 열기 · 회고 쓰기 | 작성 현황과 「회고 작성」이 함께 보이고, 안 쓴 회차가 있으면 탭 옆 점. 크루와 같은 규칙으로 쓰고 고친다 |

로컬 회귀 테스트는 `frontend/apps/core-front/src/features/meeting-retro/` 의 `model.test.ts`(끝난 회차 · 탭 점 · 순서 · 작성 현황 · 검증 · 시각 표시) · `queries.test.tsx`(👍 즉시 반영 · 실패 시 되돌림) · `RetroWriteForm.test.tsx`(미팅 종료 표시 · 수정 채움 · 제출 뒤 이동 · 못 읽으면 빈 폼 막기)에 있다.
