## 1. 의도

행사 기획을 실제 화면에서 검토할 수 있도록 간단한 신청·운영 시안 구현. 기존 사이트 UI와 유사 서비스 참고, codex가 없는 별도 브랜치 생성.

## 2. 판단

- beta 2508498a에서 feat/event-playground 생성, 기존 작업은 별도 worktree로 보존
- Luma의 행사 생성·참가자 승인 흐름 참고, 기존 StudyClub 페이지 레이아웃·공용 UI 재사용
- 결제는 모집 상세에서 안내. AUTO/REVIEW 선택, 대기·확정이 정원 점유, 거절·취소 시 자리 반환
- 폼 버전 편집·자동 리마인드·통계 대시보드는 이번 범위 밖
- 사용자 화면 명세는 events/_application/spec.ts로 분리해 기존 exporter의 동명 파일 캐시 충돌 회피. 다른 기능의 명세·PRD는 수정하지 않음

## 3. 계획

- 운영진 목록·등록·운영 상세와 회원 목록·상세·신청 제공
- 예시 데이터·브라우저 저장으로 역할 전환과 반복 체험 지원
- 신규 Story·IA·PRD·화면 설명 연결 및 상태 전이 검증

## 4. 실행

- 행사 등록·공개·모집 마감·재모집·취소 및 질문 편집 제공
- 방식별 정원, 신청 중복·마감 검증, 승인·거절·운영진 개별 취소·본인 취소 구현
- 신청 당시 질문과 답변 보존, 마감 후 참여 정보 수정 허용, 미공개 취소 행사 비노출
- 메일 예시와 수동 안내, 신청 상태 표시 및 참가 확정자 참여 링크 제공
- 한국·토론토·뉴욕·LA 시간대와 서머타임의 존재하지 않거나 중복된 시각 검증
- 독립 검토 L1/L2/L3 합격(R4)
- 브라우저 확인: 등록·질문 추가·공개·질문 잠금, 승인형 신청→승인→확정 상태, 자동 확정, 취소 자리 반환, 메일 생성, 키보드 포커스, 설명 번호, 375px 가로 넘침 없음
- build·TypeScript·lint·test:events·export-specs --check·component-drift·check-dev-scope 통과. 기존 proto.css @source 빌드 경고 유지

## 5. 잔여

- 실제 서비스 후속: API 계약·서버 권한·동시성·메일·개인정보 보유 및 삭제 정책
- 기존 공용 Tabs의 방향키와 패널 연결은 별도 개선 사항
- 예시 상태는 브라우저에 저장. 같은 탭 상단의 참가자/운영진 전환으로 검토, 다른 탭에서는 새로고침 필요
- beta 병합·배포는 검토 후 진행
