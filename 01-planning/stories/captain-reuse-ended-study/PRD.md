# ST-042 캡틴은 종료된 스터디를 복제해 새 스터디를 등록할 수 있다

## 1. 기본설명

같은 주제로 다시 모집할 때 글과 신청 질문을 다시 작성하는 수고를 줄인다. 캡틴은 상세의 「스터디 복제」 또는 스터디 등록의 「지난 스터디 불러오기」로 시작한다.

| 가져오는 값 | 새 모집에서 정하는 값 | 원본에만 남는 기록 |
| --- | --- | --- |
| 제목, 한 줄 소개, 상세 설명, 카테고리, 썸네일, 신청 질문(유형·선택지·필수 여부) | 모집 마감일, 정원(기본 제한 없음), 진행 일정, 시작일, 디스코드·드라이브 주소 | 신청 응답, 신청자, 참여자, 반, 출석 |

같은 제목을 허용한다. 스터디 ID로 구분하며 복제본에는 새 프로그램 ID를 부여한다. 신청 질문이 없으면 빈 폼으로 시작한다.

## 2. 화면명세

<!-- spec:start reuse -->

### 1 — 스터디 복제

- **조건**: 캡틴 · 일반 스터디 · ENDED 또는 CLOSED
- **동작**: 원본이 선택된 새 프로그램 등록 창을 연다. 클럽은 다음 기수 만들기를 사용한다.

### 2 — 지난 스터디 불러오기

- **조건**: 스터디 등록 › 새 프로그램 › 스터디
- **동작**: 종료된 원본을 제목과 ID로 선택한다. 제목·한 줄 소개·상세 설명·카테고리·썸네일과 신청 질문을 가져온다.

### 3 — 미공개로 등록

- **동작**: 기존 등록 검증을 적용한다. 성공하면 창을 닫고 「등록되었습니다」 토스트를 표시한 뒤 새 ID의 상세로 이동한다. 취소하면 생성하지 않는다.

<!-- spec:end reuse -->

일반 등록·기수 추가도 성공하면 창을 닫고 「등록되었습니다」 토스트를 띄운다. 공개를 바꿀 수 없으면 스위치 조작 시 사유를 토스트로 알린다.

## 3. 시스템 요건

등록 시 서버가 캡틴 권한과 원본 종류·종료 상태를 재검증한다. 새 프로그램, 스터디, 모집 정보, 새 기본 반과 신청 질문은 한 트랜잭션에서 저장한다. 질문 복사 등 어느 단계든 실패하면 모두 롤백한다. 기존 등록 응답(201)의 Location에 담긴 새 ID로 상세에 진입한다. 실패 시 입력을 유지하고 재시도할 수 있다.

원본과 복제본의 이미지는 독립적으로 유지한다. 어느 쪽에서 이미지를 교체하거나 스터디를 삭제해도 상대 이미지가 계속 보여야 한다. 신청 폼은 질문 정의만 가져오며 원본 폼 제목·설명과 응답은 제외한다. 복제 API의 마감일 생략 처리는 미결이다. 세부 요청 조합과 실패 검증은 [스터디 등록 API 명세](../../../specs/study/spec.md#원본에서-복사해-등록-st-042--스펙작성중)를 따른다.

## 4. 검증 및 계측

운영 콘솔 기능으로 퍼널·계측은 해당 없음. Playground에서는 같은 탭의 세션 저장소에서 복제본 목록·상세와 신청 폼을 확인할 수 있다. 실제 등록 API 연동은 후속 구현이다.
