# 크루는 Google 계정으로 로그인하고 온보딩을 마칠 수 있다.

기준 프로토타입: Google 로그인 · 회원가입 온보딩 (playground 사용자 사이트 · 로그인 → 온보딩)

## 1. 기본설명

· **진입·사용 흐름**

```mermaid
flowchart LR
  A["로그인 화면"] --> B["Google 로그인"]
  B --> C{"인증 결과"}
  C -->|"취소·실패"| D["오류 안내"] --> B
  C -->|"온보딩 완료 회원"| E["원래 화면 또는 홈"]
  C -->|"신규·미완료"| F["온보딩 폼"]
  F --> G{"닉네임·시간대·필수 동의 충족?"}
  G -->|아니오| F
  G -->|예| H["가입 완료"]
  H --> I{"서버 판정"}
  I -->|"형식 오류·중복"| F
  I -->|"세션 만료"| B
  I -->|성공| J["홈페이지 가입 완료 · 디스코드 연결 선택"]
  J -->|지금 연결| K{"연결 결과"}
  K -->|실패·취소| J
  K -->|성공| E
  J -->|나중에 하기| E
```

· **완료 기준**

1. Google 계정 로그인 — 다른 인증 수단 없음
2. 온보딩 완료 회원은 원래 보던 화면(없으면 홈)으로
3. 신규·온보딩 미완료 회원은 온보딩 화면으로
4. 인증 취소·실패 시 사유 안내 및 재시도
5. 닉네임 제안값(Google 이름) 자동 채움 및 수정
6. 닉네임 형식·중복 검사 — 제출 전 결과 표시
7. 시간대 선택 3종 — 기기 시간대 기본 선택
8. 필수 동의 3종 검증, 마케팅 수신은 선택
9. 약관·방침 전문 열람 및 그 자리에서 동의
10. 서버 오류·세션 만료 시 입력값 유지
11. 가입 완료 후 「지금 연결 / 나중에 하기」 선택
12. 연결 실패·취소·건너뛰기 시 가입 완료 상태 유지
13. 스터디 신청에서 진입 후 연결 성공 시 선택했던 신청 폼 복귀
14. 나중에 하기 선택 시 해당 스터디 상세 복귀, 다음 신청 시 연결 안내

### 비고

- 범위 밖: 프로필 수정, 회원 탈퇴, 백오피스 로그인

### 1 — 가입 안내

- **내용**: 구글 계정이 연결됐다는 사실과 환영 문구
- **정책**
  - 가입 절차를 말로 설명하지 않는다. 화면에 보이는 칸이 곧 할 일이다
  - 한 페이지 폼. 사진·관심 분야·거주 국가·도시·비밀번호 입력 없음

### 2 — 닉네임

- **내용**
  - 구글 이름을 제안값으로 채워 둔다
  - 오른쪽 위에 현재 글자수 / 상한
- **동작**
  - 한글 조합 중에는 검사하지 않는다. 「ㄱ」 상태에서 오류가 뜨면 치던 사람이 놀란다
  - 빈 값은 진입 즉시 말하지 않는다. 칸을 벗어나거나 제출을 누른 뒤에 말한다
- **정책**
  - trim 후 2~20자. 한글·영문·숫자·밑줄만. 밑줄만/예약어/account_ 접두사 금지
  - 허용되지 않은 문자는 **입력을 막지 않고** 알린다. 막으면 왜 안 눌리는지 알 수 없다
- **데이터**: 요청 nickname. 제안값이 없으면 빈 칸. 임시 account_ 이름은 표시하지 않음

#### 2-1 — 닉네임 상태 줄

- **내용**
  - 기본은 규칙 안내, 그 밖에는 지금 값의 상태: 확인 중 · 사용 가능 · 중복 · 형식 오류 · 검사 실패
  - 허용되지 않은 문자는 **그 글자를 따옴표로 감싸** 보여준다 (3개까지 나열, 넘으면 개수로 접는다)
  - 공백과 이모지는 따옴표로 감싸도 읽히지 않아 문장으로 따로 말한다
- **동작**
  - 형식이 맞은 값만 중복을 묻는다. 「너무 짧다」와 「이미 쓰인다」가 뒤섞이지 않게
  - 마지막 입력에서 잠시 쉬면 한 번 묻는다. 앞선 요청은 취소한다. 늦게 온 답이 최신 상태를 덮으면 안 된다
- **정책**
  - **줄을 새로 만들지 않고 도움말 자리를 바꾼다**. 상태가 바뀔 때마다 아래가 밀리면 누르려던 버튼이 움직인다
  - 서술은 「-입니다」, 행동 요청은 「-해 주세요」로 맞춘다
- **데이터**: 비교값은 앞뒤 공백 제거 → NFC → 소문자. 저장값은 입력 그대로

### 3 — 나의 시간대

- **내용**: 고른 지역. 목록을 열면 지역별 UTC 시차가 함께 보인다
- **동작**
  - 기기 시간대를 서비스의 네 선택지에 맞춰 미리 선택한다. 토론토는 뉴욕·토론토 항목으로 연결하고, 대응하지 못하면 직접 선택한다
  - 네 선택지 중 하나여야 가입할 수 있다. 방향키·Enter·Escape 지원
- **정책**
  - 실제 서비스와 같은 네 선택지다. 한국 · 서울 / 북미 동부 · 뉴욕, 토론토 / 북미 서부 · 밴쿠버 / 북미 서부 · LA
  - 시차는 값으로 고정하지 않는다. 밴쿠버와 LA는 별도 시간대로 저장하고 각 지역 규칙에 따라 계산한다
  - 라벨은 「나의 시간대」다. 「일정에 사용할 시간대」는 처음 오는 사람에게 무슨 일정인지 알 수 없다
- **데이터**: 요청 timeZone. 예: America/Vancouver. 고정 시차로 저장하지 않는다

### 4 — 약관 동의

- **내용**: 필수 셋과 선택 하나
- **정책**
  - 모두 기본 미선택. 끝까지 스크롤하게 강요하지 않는다. 열람과 동의는 별개 동작이다
  - **전문을 화면에 펴 두지 않는다**. 스크롤 박스가 세로를 먹어 정작 눌러야 할 버튼이 화면 밖으로 밀린다

#### 4-1 — 전체 동의

- **내용**: 한 번에 다 켜는 자리. 선택 항목까지 포함한다는 사실을 함께
- **동작**: 켜면 아래 넷이 다 켜진다. 아래에서 하나를 끄면 전체 동의도 풀린다
- **정책**: 선택 항목이 함께 켜진다는 것을 밝힌다. 모르고 켜면 동의를 받은 것이 아니다

#### 4-2 — 동의 항목

- **내용**
  - 만 14세 이상 · 이용약관 · 개인정보 수집·이용 · 마케팅 정보 수신
  - 각 줄이 필수인지 선택인지 드러난다
  - 마케팅 줄에는 무엇을 어디로 보내는지 한 줄로 적는다
- **정책**
  - **만 14세 이상 확인을 맨 위에 둔다**. 가입 자격이라 나머지 동의보다 앞선다 (이용약관 제3조 4항)
  - 「동의하지 않아도 가입할 수 있어요」는 적지 않는다. [선택]이 이미 그 말이다
  - 수신 매체는 따로 받는다. 지금은 이메일뿐이다. 전화번호를 받지 않아 문자를 보낼 수단이 없다
- **데이터**
  - 요청 termsOfServiceAgreed · privacyPolicyAgreed 는 true 필수
  - marketingAgreed 는 미동의일 때도 false 로 보낸다. 약관 버전·동의 시각은 서버가 남긴다
  - 미확정: 만 14세 확인과 수신 매체를 담을 필드가 없다

#### 4-3 — 약관 보기

- **내용**: 전문을 여는 자리. 읽을 문서가 있는 줄에만 붙는다
- **동작**: 누르면 전문이 열린다. 닫거나, 동의하고 닫을 수 있다
- **정책**
  - 읽고 나온 사람은 대개 동의한다. 다시 체크박스를 찾게 하지 않는다
  - 만 14세·마케팅에는 붙이지 않는다. 읽을 전문이 없다

### 5 — 가입 완료

- **내용**: 이 화면의 주액션
- **동작**
  - 닉네임·시간대·필수 동의가 다 되면 눌린다
  - **중복 검사 중에도 누를 수 있다**. 결과를 기다렸다 이어서 보낸다. 400ms 를 기다렸다 누르게 하면 다 채운 사람이 멈춰 선다
  - 제출 중에는 다시 눌리지 않는다
  - 가입 저장 성공 후 디스코드 연결 선택 안내로 이동한다. 이 시점에 홈페이지 가입은 완료된다
- **정책**: 버튼 아래에 필수 항목 안내를 적지 않는다. [필수] 표기와 같은 말이고, 못 채운 칸에서 멀다
- **데이터**: POST /accounts/onboarding → 200. 이 프로토는 같은 모양의 요청을 화면에서만 처리한다

### 6 — 오류 안내

- **조건**: 서버 오류 또는 세션 만료
- **내용**: 오류 이유 · 재시도 또는 다시 로그인
- **동작**: 세션이 만료돼 다시 돌아와도 쓰던 값을 이어서 작성한다
- **정책**
  - 400 형식 오류는 해당 필드, 409 중복은 닉네임 줄, 401 은 재로그인. **오류가 나도 입력은 지우지 않는다**
  - 검사 시점과 제출 사이에 다른 사람이 같은 이름을 가져갈 수 있다. 서버 판정이 최종이다

  - 스터디는 디스코드에서 진행돼요. 지금 연결할까요?
- **정책**
  - 온보딩 저장 성공 후에만 노출한다. 디스코드 연결 선택과 홈페이지 가입 완료는 독립적이다.
  - **부제를 두지 않는다** — 언제 연결하는지는 아래 두 버튼이 이미 말한다

### 2 — 지금 연결

- **내용**: 지금 연결
- **동작**
  - 연결 중 중복 요청을 막는다
  - 성공 후 안전한 next 경로로 돌아간다. 스터디 신청에서 왔다면 선택한 스터디의 신청 폼을 바로 연다
- **데이터**: POST /api/me/discord/link 성공 후 GET /api/me 재조회. Playground 예시 핸들은 jiwon_dev

### 3 — 스터디 먼저 둘러보기

- **내용**: 스터디 먼저 둘러보기
- **동작**
  - 가입 완료를 유지하고 원래 화면 또는 홈으로 이동한다
  - 스터디 신청에서 왔다면 선택한 스터디 상세로 돌아간다. 다시 신청하기를 누를 때 연결을 요구한다
  - 진행 중인 연결 시뮬레이션을 취소한다
- **정책**: 외부 URL·로그인·온보딩으로 돌아가는 next는 홈으로 대체한다

### 4 — 연결 실패·취소

- **조건**: 연결 실패 또는 인증 취소 시
- **내용**
  - 디스코드에 연결하지 못했어요. 잠시 후 다시 시도해 주세요.
  - 디스코드 연결을 취소했어요. 다시 연결할 수 있어요.
- **동작**: 지금 연결로 재시도하거나 스터디 먼저 둘러보기로 이동한다
- **정책**: 가입 완료 상태를 유지한다. 연결 성공 전에 연동 상태를 바꾸지 않는다

## 3. 시스템 요건

### 개발 범위

> 2026-10-28 `beta` 기준 (온보딩 연결 선택 · 신청 복귀). **지금 → 할 일**만 적는다. 다 끝나면 「할 일」이 모두 「없음」이 된다.
> FE 「지금」은 실제 앱의 화면과 데이터 연결(API · mock)까지 본 값이다 — 완료 기준 하나하나의 동작은 따로 확인하지 않았다.
> BE 「지금」은 스펙 엔드포인트 표의 상태 칸을 옮겨 적는다.

| 구분 | 대상 | 지금 | 할 일 |
|---|---|---|---|
| FE | core-front `/login` · `/onboarding` | 있음 — 구글 로그인 · 닉네임 확인 · 온보딩 API · 가입 후 연결 선택(`?step=discord`) · 신청 `apply=1` 복귀 | 없음 |
| BE | `POST /auth/social-login` · `GET /api/me` · `GET /api/nicknames/availability` · `POST /accounts/onboarding` | 구현완료 | 없음 |
| Playground | 가입 후 연결 선택 | 구현 · 브라우저 시뮬레이션 | 없음 |
| BE | `POST /api/me/discord/link` | 구현완료 — 프론트 OAuth 팝업 연결됨 (DSC-04) | 없음 |

### 데이터

| 대상 | 필드 | 의미 |
| --- | --- | --- |
| 계정 | NICKNAME | 필수. 저장은 입력 그대로, 비교는 정규화 값 |
| 계정 | TIME_ZONE | 필수. IANA id. 고정 시차로 저장하지 않는다 |
| 계정 | ONBOARDING_COMPLETED_AT | null 이면 온보딩 미완료 |
| 로그인 수단 | ISSUER, PROVIDER_ACCOUNT_ID | 사람 찾기 키. 이메일로 찾지 않는다 |
| 동의 | CONSENT_TYPE, AGREED, AGREED_AT, CONSENT_VERSION | 이용약관·개인정보는 AGREED=true 여야 저장 |

### 처리

- 로그인: Google code 교환 → `(ISSUER, sub)` 로 계정 조회 → 없으면 계정과 로그인 수단을 만든다
- 온보딩: 닉네임·시간대·동의를 한 트랜잭션으로 저장하고 `ONBOARDING_COMPLETED_AT` 을 채운다
- 저장 성공 후 디스코드 연결 선택. 연결 실패·취소에도 홈페이지 가입 완료 유지
- 신청 복귀 주소는 내부 경로만 허용. Playground는 숫자 study_id 상세 주소에 apply=1로 신청 의도 보관, 처리 후 제거
- 나중에 하기는 신청 의도만 제거하고 선택한 상세로 복귀. 실제 OAuth는 state 검증 후 안전한 복귀 주소 사용
- 닉네임 중복은 정규화 값으로 판정한다. 제출 시 다시 판정한다
- 실패 응답: 400 형식 · 401 세션 만료 · 409 중복
