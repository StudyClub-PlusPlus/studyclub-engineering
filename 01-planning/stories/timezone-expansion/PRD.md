# 시간대 확장

> 2026-11-22 · 개발 기준. [공통 정책](../../_registry/policies/POL-0006-timezone.md). beta 반영 완료를 의미하지 않는다.

## 1. 데이터 구분

| 값 | 용도 | 변경 시 유지할 값 |
|---|---|---|
| 회원 시간대 | 회원 화면의 시각 표시 | 반 배정·신청 답변·모집 범위·일정 UTC |
| 모집 시간대 | 모집 안내·검색 | 반 기준 시간대·일정 UTC·신청 자격 |
| 반/행사 기준 시간대 | 일정 입력·반복 기준 | 명시적으로 수정하지 않은 기존 회차 UTC |
| 백오피스 표시 시간대 | 헤더에서 정하는 운영자별 표시·대시보드 집계 기준 | 회원 프로필·반/행사 기준·마감 UTC |

- 지역은 IANA ID, 실제 순간은 UTC로 저장한다. 같은 오프셋의 다른 지역은 합치지 않는다.
- 모집 범위로 신청을 차단하거나 반을 자동 편성하지 않는다.

## 2. 선택기

- 온보딩·내 정보·반/행사 기준: 전체 지역, 한 칸 검색, 국가별 제목. 국가/도시 한국어·영어·IANA ID 검색.
- 순서: 한국 → 미국 → 캐나다 → 호주 → 영국 → 나머지 국가명 순. 미국은 뉴욕·LA, 캐나다는 토론토·밴쿠버 우선. 나머지 도시는 화면 언어의 이름순.
- 온보딩은 기기 시간대 제안, 알 수 없으면 직접 선택. 필수 입력. 추가 안내 문구 없음.
- 내 정보는 저장 성공 즉시 적용. 취소·실패는 기존 값 유지. 기기 변경에도 저장값 유지.

## 3. 회원이 있는 시간대 후보

- 헤더·모집 선택기 기본 후보: **온보딩 완료·비탈퇴 전체 계정** 중 시간대별 1명 이상. 휴면·캡틴·스터디 미참여 포함, 계정 ID 중복 제거.
- 후보는 페이지 **재진입·새로고침**에 갱신. 열린 목록·드롭다운 재오픈·탭 포커스 복귀에서는 유지. 같은 페이지는 같은 집계 시점 사용.
- 헤더·모집 모두 열 때마다 회원 후보부터 표시. ‘전체 시간대에서 찾기’로 전체 지역 검색, 회원 후보로 복귀 가능. 검색어는 유지하며 모집 모드는 바뀌지 않음.
- 0명이 된 지역은 다음 갱신에서 기본 후보에서 제외하되, 헤더·모집의 기존 선택값은 목록과 저장값에 유지. 후보 0개여도 기존 선택 표시·전체 지역 검색 가능.
- 헤더 기본값: 이 브라우저의 운영자별 유효 저장값 → 프로필 → 기기 → 한국. 회원 수 변화로 선택값을 대체하지 않음. 프로필 변경 없음.
- 조회 실패는 빈 집계와 구분: 이전 후보 유지·재시도 제공. 첫 조회 실패에도 기존 선택·전체 지역 검색 유지. 다음 진입 요청에 최신 집계가 반영되도록 서버 캐시 무효화.

## 4. 모집 시간대·검색

- 저장: `mode: unset | all | selected`, `zones: IANA[]`. `selected`는 중복 없는 유효 지역 1개 이상, 나머지 모드는 빈 배열.
- 전체 모집은 미래 지역도 포함. 현재 모든 후보를 체크한 `selected`와 구분. 미정은 전체 모집으로 자동 변환하지 않음.
- 배포 전 기존 모집 값은 KST → 한국(`Asia/Seoul`), PST → LA(`America/Los_Angeles`), BOTH/both → 한국+LA로 일괄 이관. 미정은 유지하며 일정 문구에서 추정하지 않음. 이미 IANA ID로 저장된 밴쿠버 등은 변경하지 않음.
- 검색 후보: **공개 스터디 전체**의 특정 모집 지역. 종료 포함·비공개 제외. 다른 필터·페이지네이션으로 후보를 줄이지 않음.
- 한국+LA는 한국 또는 LA 필터에서 모두 표시. 조합 옵션 없음. 전체 모집·미정은 모든 지역 필터에 포함하되 지역 후보를 만들지는 않음.
- 선택 지역이 목록 갱신으로 사라지면 필터를 전체로 초기화. 전체/미정만 있으면 ‘모집 시간대 전체’만 표시.
- 모집 표기: 서울은 ‘한국’, 로스앤젤레스는 ‘미국 · LA’. 저장 ID 변경 없음.

## 5. 일정 표시·입력

- 회원 표시: 프로필 → 기기 → 한국. 사용자 사이트 캡틴·네비게이터의 회차 표는 전체 지역 검색으로 임시 전환 가능하며 조회·기존 회차 수정에만 적용한다. 백오피스 표시: 헤더. 구조화된 시각에 해당 날짜 약칭(없으면 UTC 오프셋), 24시간제 적용.
- 적용: 회차·출석·행사·문의 접수·알림 요청/발송·템플릿 수정·대시보드 갱신 시각.
- 신규 반/회차 입력은 반 기준, 행사 입력은 행사 기준. 중복 기준 안내 문구 없음. 아래에 환산 시각 표시(사용자 사이트: 프로필 → 기기 → 한국, 백오피스: 헤더), 같은 시간대면 생략.
- 반복은 반의 현지 요일·시각 유지. 기간 중 상대 시차가 달라지는 회차에만 변화 안내.
- DST는 기존 회차 생성 처리 유지: 없는 현지 시각은 수정 필요, 중복 시각은 해당 날짜의 전환 전/후 선택. 미해결 날짜가 있으면 반복 전체 생성 차단. 기존 회차와 날짜가 겹칠 때 건너뛰는 규칙은 별개로 유지. 기존 값을 되돌리면 원래 UTC 유지.
- 백오피스 개별 회차 직접 수정은 헤더 기준. 날짜·시간 편집 중 헤더 변경 차단, 저장/취소 후 해제.
- 모집 화면의 자유 일정 문구는 자동 환산하지 않음. 입력 예시만 ‘매주 목 20:00 KST · 8주 과정’. 가상 확정 일정·‘내 시간대’ 행 추가 없음.

## 6. 모집 마감

- UTC 순간 하나로 공통 판정. `현재 시각 >= 마감`이면 마감. 기존 정원·공개·상태 조건 유지, 서버가 신청 가능 여부 최종 판정.
- 날짜 입력은 입력 당시 헤더 시간대의 23:59:59로 변환. 마감 미수정·표시 시간대 변경은 기존 UTC 유지.
- 상세·신청서·백오피스 목록/상세: 조회 기준 날짜+시각+약칭. 코어 카드는 배지만, 대시보드는 짧은 날짜+D-N과 전체 시각 보조 정보.
- D-day = 조회 기준의 마감 날짜 − 오늘 날짜. 마감 판정 후, 열려 있을 때만 표시. 코어 D-DAY / 백오피스 D-0. 임박 색상은 기존 D-3 기준.
- 열린 화면은 마감 순간·백그라운드 복귀에 재판정. 마감 후 제출은 기존 흐름대로 폼을 닫고 상세 CTA를 모집 마감으로 변경.

## 7. 대시보드

- 분포 대상은 기존 활동 크루, 계정별 1회. 헤더 후보의 전체 회원과 구분.
- 5개 이하면 모두, 초과하면 상위 4개+기타. 인원 내림차순·동률 IANA 순. 퍼센트 임계값 없음.
- 기타: hover/focus 요약, 클릭/탭 상세. 동일 글꼴·크기. 상세 비율도 전체 크루가 분모.
- 실제 누락만 미설정으로 별도 표시하고 5자리 중 하나 사용. 정상 온보딩 표본에 미설정 생성 없음.
- 대시보드 주간 출석 경계는 헤더 지역 월요일 00:00. API에 헤더 지역을 전달하고 서버는 프로필로 덮어쓰지 않는다. 응답·캐시도 요청 지역을 구분한다. 다른 집계의 기존 경계는 유지.

## 8. 구현 경계·확인 사항

- Playground: 명시적 예시 회원 + 브라우저 저장. 운영 회원/서버와 연결되지 않음. 기존 날짜 전용 mock은 KST 일말 UTC를 명시한 표본이며 운영 데이터 이관 규칙이 아님.
- 스터디 전체 CRUD·반 설정 영구 저장은 이번 Playground 범위 밖. beta에는 저장 연결이 있으나 기존 제한된 시간대·KST/PST/BOTH 계약은 별도 확장 필요.
- 개발 전 확인: ① 날짜만 저장된 기존 마감의 원본 시간대와 미설정 회원의 복구 기준 ② 서버/클라이언트 공통 지역·별칭·시간대 규칙 ③ 반 기준 변경 시 기존 회차 이동은 담당 스쿼드 계약 유지.
- 확인 전 누락값을 한국·전체 모집으로 일괄 변환하지 않음. 데이터 예외가 발견되면 대상과 처리안을 기획 확인.

## 9. 필수 검증

- 회원 변경 → 본인 즉시, 후보 다음 진입/새로고침. 마지막 회원 이탈·중복 참여·조회 실패.
- 헤더·모집의 회원 후보/전체 검색 전환, 회원 0명인 기존 선택 보존, 후보가 없어도 전체 검색 가능.
- PST→LA·BOTH→한국+LA 이관, 한국+LA OR 검색, 전체/미정 포함, 비공개 후보 제외.
- DST 전후 반 현지 시각 유지·중복/없는 시각 처리.
- 마감 1ms 전/동일/직후를 한국·LA·토론토에서 비교. D-day만 달라도 신청 가능 여부 동일.
- 헤더 변경 전후 저장 UTC 동일. 자유 일정 문구 유지. 취소·실패 시 집계 불변.
