# POL-0008 · 화면 공통 규칙

> 시행일: 2026-10-10 · 적용: 운영 콘솔 · 사용자 사이트 전 화면
> 화면마다 다르게 굴면 쓰는 사람이 매번 다시 배운다. 여러 화면에 똑같이 적용되는 것만 모은다.

## 모달 닫기

모든 모달은 **우상단에 X** 를 둔다. `Esc` 는 X 와 똑같이 동작한다. **배경 클릭으로는 닫히지 않는다** —
쓰던 것이 사라지는 창을 스쳐 누르다 잃는 일이 생긴다.

하단 버튼은 모달 성격에 따라 셋으로 나뉜다.

| 성격 | 예 | 하단 버튼 |
|---|---|---|
| **읽기 전용** | 약관 전문, 명단 보기 | 없음. X 만 |
| **입력·설정** | 공개하기, 필터, 템플릿 추가 | 액션 하나. **취소를 두지 않는다** |
| **결정을 묻는다** | 삭제, 탈퇴, 거절 | **취소 + 액션.** 취소가 기본 포커스를 받는다 |

- 입력·설정 모달은 닫으면 작성 중이던 입력이 그대로 사라진다. 확인 창을 띄우지 않는다
- 결정을 묻는 모달은 **Enter 로 액션이 실행되면 안 된다** — 기본 포커스는 취소에 둔다.
  액션 버튼은 파괴적 동작임이 드러나게 표시한다
- X · `Esc` · 취소는 모두 같은 결과(닫기)를 낸다
- 결정을 묻는 모달에만 취소를 두는 이유는 **안전한 선택지가 버튼으로 보여야** 하기 때문이다.
  X 하나만 두어 **액션 버튼이 화면에서 유일한 버튼이 되는 구성은 만들지 않는다**
- X 에는 `aria-label="닫기"` 를 넣는다
- **제목은 하는 일만** 적는다 — 「스터디 시간 수정」 · 「회차 추가」. 대상(어느 반 · 어느 스터디)은 제목에 붙이지 않고
  `Modal` 의 `description`(제목 아래 작은 글씨)에 둔다. 제목이 대상마다 바뀌면 같은 창이 다른 창처럼 보인다 (2026-10-15)

## 거르는 드롭다운

**고르기 전에는 축 이름만 보인다.** 「상태 전체」·「카테고리 전체」처럼 적지 않는다 — 이미 무언가
걸러 둔 것처럼 읽힌다.

| 때 | 첫 줄 | 왜 |
|---|---|---|
| 아직 고르지 않음 | **축 이름** (「상태」 · 「카테고리」) | 무엇을 고르는 칸인지만 말한다 |
| 하나 고른 뒤 | **「전체」** | 되돌아갈 길이 그 자리에 생긴다 |

- 고르지 않은 축은 계속 축 이름을 유지한다 — 축마다 따로 움직인다
- 필터를 바꾸면 첫 페이지로 돌아간다. 3페이지를 보던 중에 거르면 그 페이지가 없을 수 있다
- 고른 값은 저장하지 않는다. 새로고침하면 처음 상태로 돌아간다

## 버튼

- 버튼 문구는 **그 버튼이 하는 일**을 적는다 — 「확인」보다 「삭제」·「저장」
- 되돌릴 수 없는 동작은 그 사실을 버튼 옆 한 줄로 알린다
- **모양은 행동의 성격으로 정한다** — 같은 행동은 어느 화면에서나 같은 모양이다 (2026-10-15)

| 성격 | 예 | 모양 (`@studyclub/ui` Button) |
|---|---|---|
| 주 행동 — 한 묶음에 하나 | 저장 · 만들기 · 회차 추가 | `primary` 채움 |
| 보조 행동 | 수정 · 반 추가 | `secondary` 테두리 |
| 되돌리기 | 취소 · 변경 취소 · 선택 해제 | `tertiary` 글자 (구 ghost) |
| 지우기 · 내보내기를 연다 | 삭제 · 참여 중단 | `danger` 빨간 테두리 |
| 지우기 마지막 확인 | 확인 모달의 「삭제」 | `destructive` 빨간 채움 |

- 한 줄에 함께 두면 되돌리기는 왼쪽, 주 행동은 오른쪽 끝
- 지우는 버튼은 숨기지 않는다 — 고를 것이 있어야 하면 잠가 두고 이유를 알린다

## 표 맨 위 작업 바

고르고 · 고치고 · 저장하는 표(참여 크루 · 출석부 · 일정 표)는 표 카드 **맨 위**에 **한 줄** 작업 바를 둔다. `@studyclub/ui` `TableActionBar` (2026-10-15, 위치는 2026-10-18 표 아래 → 맨 위).

```
┌ 표 카드 ───────────────────────────────────────────────────────────┐
│ [3명 선택] [반 변경 ▾] [역할 변경 ▾] [선택 해제]          [변경 취소] [저장] │
│ └──────── 왼쪽: 고른 것에 하는 일 ────────┘          └ 오른쪽: 저장 ┘ │
├────────────────────────────────────────────────────────────────────┤
│ 표 머리 · 줄 …                                                      │
```

- **한 줄이다.** 선택 줄과 저장 줄을 따로 쌓지 않는다. 두 줄이면 어느 버튼이 무엇에 걸리는지 흐려진다
- **자리는 표 카드 안 맨 위.** 스크롤하면 사이트 머리 아래에 붙어 따라온다. 일정 · 출석 · 참여 크루가 같은 자리
- **왼쪽 = 고른 것에 하는 일.** 맨 앞 「n명 선택」(사람) · 「n개 선택」(회차): 숫자가 앞. 일괄 변경 드롭다운 · 삭제 · 참여 중단, 고른 뒤에만 「선택 해제」
- **「적용」 버튼을 두지 않는다.** 일괄 변경 드롭다운(반 · 역할 · 출석 상태)은 마우스로 고르는 순간(키보드는 화살표로 옮긴 뒤 Enter 를 누르거나 칸을 떠날 때) 고른 줄에 저장 전 변경으로 얹힌다. 드롭다운은 다시 처음 글(「반 변경」 · 「출석 상태」)로 돌아온다. 되돌리기는 「변경 취소」
- **화살표 이동만으로는 반영하지 않는다.** 접힌 드롭다운은 화살표 키마다 값이 바뀐다. 그때마다 반영하면 키보드로 목록을 훑기만 해도 첫 항목이 고른 줄 전원에 얹힌다(WCAG 3.2.2). 키보드는 Enter 나 칸을 떠날 때 확정한다
- **오른쪽 = 저장.** 「저장」은 늘 있고 고친 것이 없으면 잠긴다. 고친 것이 있을 때만 앞에 「변경 취소」
- **고르기 전에도 보인다.** 「0명 선택」 · 드롭다운 · 버튼은 잠기고 옅은 회색(비활성 색 `disabled-bg` · `disabled-fg`). 한 명이라도 고르면 살아난다. 고를 수 있는 표라는 것과 지우는 길을 먼저 보여 준다
- **고른 것과 상관없는 일은 넣지 않는다.** 「반 추가」 · 「회차 추가」는 표 제목 줄 오른쪽
- **표 제목 옆 개수는 전체만.** 「전체 N」. 고른 수는 작업 바의 「n명 선택」 한 곳에만 둔다
- 바탕은 표 카드와 같은 색, 아래에 표와 가르는 선 하나. 띠 · 그림자를 넣지 않는다
- 버튼 모양은 위 「버튼」 표를 따른다

## 표

- 비어 있을 때도 표 자리의 높이를 지킨다 — 상태가 바뀔 때마다 화면이 들썩이지 않게
- **못 읽은 것과 한 건도 없는 것을 구분한다.** 조회 실패를 「0건」으로 보여주지 않는다

## 문서 경계

같은 내용을 두 문서가 말하면 한쪽만 고쳐진다. 어디에 무엇을 적는지 먼저 가른다.

| 문서 | 자리 | 담는 것 | 쓰는 사람 |
|---|---|---|---|
| **PRD** | `01-planning/stories/<slug>/PRD.md` | 무엇을 만드는가 — 화면·동작·정책·필요한 데이터와 API 계약 | 기획 |
| **POL** | `01-planning/_registry/policies/` | 여러 화면에 걸치는 값 — 상태·권한·표기 규칙 | 기획 |
| **spec** | `specs/<기능>/spec.md` | 어떻게 만드는가 — 스키마·마이그레이션·배치·동시성·에러 코드 | 개발 |

- **개발은 「무엇을」이 궁금하면 PRD 하나만 본다.** 화면 설명을 spec 에 또 적지 않는다
- PRD 는 POL 의 값을 복붙하지 않고 **ID 로 링크**한다 — 상태가 5종이라는 사실을 PRD 20개에 적으면
  한 번 바뀔 때 20곳을 고쳐야 한다
- **PRD 의 화면명세는 손으로 쓰지 않는다.** 프로토의 `spec.ts`(화면의 「설명 보기」)가 원본이고,
  `pnpm --filter playground export-specs` 가 PRD 의 `<!-- spec:start -->` 자리에 넣는다.
  **플레이그라운드 = 설명 보기 = PRD** 가 늘 같아야 하기 때문이다. CI 가 어긋남을 막는다

## 저장을 기다리는 동안

- **저장되기 전에 화면을 바꾸지 않는다.** 누른 값으로 미리 바꾸면 저장에 실패해도 바뀐 것처럼 남아,
  다시 눌러야 한다는 사실을 알 수 없다. 지금 저장돼 있는 것이 보여야 하는 값은 특히 그렇다 (권한·상태)
- 기다리는 동안 **누른 자리를 잠그고 기다리는 중임을 그 자리에 알린다** — 두 번 눌러 두 번 저장되지 않게
- 저장되면 바뀐 값을 그린다. 실패하면 **원래 값 그대로 두고** 사유와 다시 시도를 알린다.
  **결과를 창으로 띄우지 않는다** — 끝난 일을 다음 일 하려고 또 닫게 만들지 않는다
- **끝났다는 말을 어디에 두는가는 그 결과가 보이는 자리가 정한다.**
  - **그 줄에서 값이 바뀌어 보이면 그 자리에 적는다** — 마이페이지처럼 **줄마다 따로 저장**하는
    화면은 바뀐 줄 옆에 「저장됨」을 띄운다. 토스트는 어느 줄이 저장됐는지 말하지 못하고,
    눈이 화면 아래로 갔다가 되돌아와야 한다
  - **체크박스에는 아무 말도 붙이지 않는다** — 켜졌는지 꺼졌는지가 곧 결과다
  - **그 자리만 봐서는 알 수 없는 것은 토스트로 한 번** — 바뀐 값 말고 더 할 말이 있거나(권한을
    바꿨으니 디스코드도 따로 바꿔야 한다), **여러 건을 묶어** 알릴 때(재발송 12건의 결과)
  - 한 화면 안에서 **두 방식을 섞지 않는다** — 같은 카드의 어떤 줄은 옆에, 어떤 줄은 아래에서
    알리면 저장이 두 가지 일인 것처럼 읽힌다
