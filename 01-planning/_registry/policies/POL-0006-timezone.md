# POL-0006 · 시간대와 지역

> 시행일: 2026-09-22 · 적용: 온보딩 · 프로필 수정 · 반 편성 · 출석 명부 · 스터디 일정 · 운영 대시보드
> 백엔드 대응: [`docs/erd/ACCOUNT.md`](../../../docs/erd/ACCOUNT.md) (`TIME_ZONE`)

## 고를 수 있는 값

| 표기 | IANA ID |
|---|---|
| 한국 · 서울 | `Asia/Seoul` |
| 북미 동부 · 뉴욕, 토론토 | `America/New_York` |
| 북미 서부 · 밴쿠버 | `America/Vancouver` |
| 북미 서부 · LA | `America/Los_Angeles` |

## 판정 규칙

- **시간대가 곧 거주 지역이다.** 지역을 따로 받지 않고 시간대에서 파생한다 —
  `Asia/Seoul` 이면 한국, 그 밖이면 북미. 값을 두 개 받으면 서로 어긋난다
- **반이 갈리는 단위가 이 값이다.** 같은 시간에 모일 수 있는 사람끼리 묶는다
- 오프셋(+9, -4 …)을 저장하지 않는다. **지역별 규칙과 회차 날짜로 계산한다** —
  밴쿠버와 LA를 같은 시간대 값으로 합치지 않는다. 밴쿠버는 2026-03-08의 마지막 봄 전환 이후 연중 UTC−7(PCT), LA는 여름 PDT(UTC−7)·겨울 PST(UTC−8)다. 2026-11-01 이후 겨울에는 밴쿠버가 LA보다 한 시간 빠르다
- 가입 때 브라우저 시간대를 위 네 선택지에 맞춰 미리 고른다. 토론토는 뉴욕·토론토 항목에 대응하고, 대응하지 못하면 직접 선택한다
- 마이페이지의 내 정보 수정에서 닉네임·시간대를 함께 저장한다. 취소하면 둘 다 기존 값을 유지한다
- 온보딩과 프로필 수정이 **같은 선택지·같은 표기**를 쓴다

## 날짜·시간 표기

- 서버는 UTC 로 주고받는다
- 내 스터디룸의 주간 일정·카드와 참여자용 회차 일정·출석표 날짜는 **프로필 시간대 → 브라우저 시간대 → 서울** 순서로 표시한다. 거주 권역만으로 북미를 서부 시간에 묶지 않는다
- 화면 제목에 `내 시간대: 뉴욕·토론토(ET)`처럼 지역과 약칭을 함께 표시한다. 조회 화면의 KST/PT 전환 버튼은 제거하고 마이페이지 설정을 따른다
- 내 스터디 일정·출석 상단의 정규 운영 시간도 프로필 시간대로 환산한다(예: `매주 수요일 06:30 · 뉴욕·토론토(EST)`). 가까운 예정 정규 회차 날짜를 기준으로 시차를 계산하며, 예정 회차가 없으면 마지막 정규 회차, 회차 자체가 없으면 오늘을 기준으로 한다. 정규 요일·시각 설정은 그대로 유지하고 개별 회차의 예외 변경을 정규 시간으로 삼지 않는다
- 정규 시간 옆 ⓘ는 `반 기준: 원래 운영 시간`과 `서머타임에 따라 내 지역의 시간이 달라질 수 있어요.` 두 문장으로 간단히 안내한다. 환산 기준 날짜와 별도의 `다음 모임` 줄은 표시하지 않는다
- 새 회차 추가는 내 프로필 시간대로 입력한다(프로필 → 브라우저 → 서울). 기본값은 반의 다음 운영 일정을 내 날짜·시각으로 환산해서 채우며, 반복 요일·시각·종료일도 입력하는 내 시간대 기준이다. 표에서 임시로 다른 지역을 골라도 추가 창은 내 프로필 기준으로 열린다
- 기존 회차 표도 내 프로필 시간대로 시작하고 서울 / 뉴욕·토론토 / 밴쿠버 / LA로 전환할 수 있다. 별도의 수정 버튼 없이 보이는 시간대로 칸을 바로 고친다. 메뉴 제목은 `시간대`, 안내는 `선택한 지역의 시간으로 입력해 주세요.`다
- 시간대만 전환하면 같은 순간을 환산해 보여주며 저장값은 바꾸지 않는다. 날짜·시각을 직접 고친 뒤 저장하면 선택한 지역의 입력을 UTC로 변환한다. 프로필·반 시간대는 바꾸지 않는다
- 모집 목록·상세는 확정된 모임의 날짜·시각·원본 시간대가 모두 있는 경우에만 보는 사람의 시간대로 바꾼다. 시작 예정일만 있거나 자유 문구·시간대 미정인 경우는 기존 내용을 유지한다. 모집 화면에는 시간대 전환 메뉴를 추가하지 않는다
- 출석 판정·하루 한 회차 중복 판정·킥오프 이후 여부는 해당 반의 시간대를 유지한다. 입력 날짜가 전날·다음 날이어도 반의 날짜로 환산해 검사한다. 표시 시간대가 판정·집계 기준을 바꾸지 않는다. 반복 생성은 입력자의 지역에서 선택한 요일·시각을 유지하므로 서머타임 경계에서는 반에서 보는 시각이 달라질 수 있다

## 시간 표기 규칙

| 무엇 | 규칙 | 예 |
|---|---|---|
| 시각 | **24시간제.** 오전·오후를 붙이지 않는다 | `20:00` · `09:00` |
| 기준 시간대 | 보는 사람의 시간대로 바꿔 적는다 | 서버는 UTC 로 주고받는다 |
| 시간대 약칭 | 날짜 없는 지역 선택은 동부 ET·LA PT·밴쿠버 PCT, 개별 회차는 해당 날짜의 EDT/EST·PDT/PST·PCT | `밴쿠버(PCT)` · `2026-11-04 03:30 PST` |
| 날짜 | 연-월-일 순서. 자릿수를 맞춰 세로로 읽히게 | `2026-10-05` · `26. 10. 05.` |
| 남은 날 | `D-N`. 지난 것만 따로 구분한다 | `D-4` · 마감 경과 |

- **24시간제로 통일한다** — 회차 시각 · 반 이름 · 지역 시계 · 알림 발송 이력이 모두 그렇다.
  오전·오후는 한 자리만 달라도 같은 화면 안에서 두 가지 읽기가 생긴다.
- 날짜가 정해진 회차에는 해당 순간의 약칭을 붙인다. 오늘의 약칭이나 고정된 PDT를 다른 날짜에 재사용하지 않는다.
- 밴쿠버의 2026년 변경은 오래된 브라우저·서버 시간대 데이터에서도 동일하게 적용한다. 프로필과 일정에는 `America/Vancouver`를 유지하며, 변환 시에만 마지막 봄 전환(2026-03-08 10:00 UTC) 이후 UTC−7 규칙을 적용한다. 그 이전 날짜에는 기존의 서머타임 이력을 따른다. 프로필 선택지의 UTC 시차·일정 입력·조회·모집 확정 일정에 같은 규칙을 사용한다.
  근거: [BC 정부의 연중 UTC−7 전환 안내](https://archive.news.gov.bc.ca/releases/news_releases_2024-2028/2026AG0013-000209.htm), [PCT 약칭 안내](https://news.gov.bc.ca/releases/2026CITZ0009-001073).

## 집계의 경계

- **주 단위로 묶는 값의 경계는 한국 시간이다** — 주별 출석률처럼 회차를 주로 묶는 값이 그렇다.
  한국 월요일 새벽 회차는 다른 시계로는 아직 일요일이라, 기준이 없으면 **같은 회차가 보는 사람마다
  다른 주에 들어간다.** 보여줄 때만 보는 사람의 시간대로 바꾼다 — 자르는 기준과 읽는 기준은 다른 일이다
- **운영 대시보드의 주간 출석 집계는 예외로 조회자 시간대의 월요일 00:00 에서 자른다** — 전주 대비 출석률과
  최근 12주 추세가 그렇다. 운영진의 시간대에 따라 출석률이 다를 수 있다. 시간대는
  [dashboard 스펙](../../../specs/dashboard/spec.md) 2.2 를 따른다 — 브라우저 시간대가 먼저고, 없으면 회원 설정이다
  (→ [share 10-15](../../../docs/share/2026-10-15-dashboard-week-boundary.md))
- **집계는 서버 한 곳에서 한다.** 화면은 끝난 숫자를 받아 그린다 — 식이 화면마다 따로 있으면
  같은 값을 두 화면이 다르게 말하고, 그런 어긋남은 찾기 어렵다
