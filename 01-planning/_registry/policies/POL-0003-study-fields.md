# POL-0003 · 스터디 정보 항목

> 시행일: 2026-09-22 · 적용: 스터디 등록 · 수정 · 공개 · 사용자 사이트 스터디 상세
> 백엔드 대응: [`docs/erd/STUDY.md`](../../../docs/erd/STUDY.md) (기수 운영값) · [`docs/erd/STUDY_PROGRAM.md`](../../../docs/erd/STUDY_PROGRAM.md) (종류·정체성) · [`docs/erd/STUDY_RECRUITMENT.md`](../../../docs/erd/STUDY_RECRUITMENT.md) (모집 기간·정원) · [`specs/study/spec.md`](../../../specs/study/spec.md)

## 프로그램 · 종류

프로그램은 따로 등록하지 않는다 — 첫 스터디를 등록하면 프로그램과 첫 기수가 한 번에 만들어진다.
종류(`STUDY` 한 번 진행 / `CLUB` 기수제 반복)는 이때 정하고, **한 번 정하면 바꾸지 못한다.** 클럽의
새 기수는 등록 폼의 「기존 클럽의 새 기수」 또는 운영 화면의 「다음 기수 만들기」로 붙인다 —
[STUDY_PROGRAM](../../../docs/erd/STUDY_PROGRAM.md).

## 받는 항목

| 항목 | 필수 | 값 | 비고 |
|---|---|---|---|
| 제목 | 필수 | 한 줄 | 60자 이내 |
| 한 줄 소개 | 필수 | 한 줄 | |
| 주제 | 필수 | 정해진 목록에서 고름, 최대 3개 | 첫 번째가 대표(목록 카드 색·아이콘 기준) |

| 진행 일정 | 선택 | 자유 텍스트 | 모집 때 알리는 문구(예: "매주 목 20:00 · 8주 과정"). 반이 실제로 갖는 요일·시간과는 별개 |
| 모집 마감일 | **필수** | 날짜 | 모집 상태 판정 축 ([POL-0002](POL-0002-study-status.md)) |

| 진행 시작일 | 선택 | 날짜 | 모임이 실제로 시작하는 날. 모집 마감일·진행 일정과는 다른 값 |
| 디스코드 채널 주소 | 선택 | URL | 참고용 링크 하나. 자동화(채널 목록 조회·삭제 감지)의 근거로 쓰지 않는다 — [POL-0002](POL-0002-study-status.md) |
| 자료 드라이브 주소 | 선택 | URL | 참고용 링크 |

**받지 않는 항목과 이유**

| 항목 | 이유 |
|---|---|
| 진행 방식(온라인/오프라인/혼합) | 전 스터디 온라인 운영이라 선택지가 무의미. 필드 자체를 두지 않는다 |
| 신청 링크 | 사이트 자체가 신청 창구. 외부 폼 링크를 받지 않는다 |
| 모집 시작일 | 모집 상태를 가르는 축은 마감일 하나다. 모집 시작 = 공개(아래) |
| 공개일 | 등록하면 항상 미공개로 들어가고, 공개는 목록에서 캡틴이 따로 켠다. 예약 공개는 없다 — 준비가 됐는지는 날짜가 판단할 수 없다 |
| 진행 종료일 | 회차 일정을 규격화된 폼으로 받지 않아 종료일을 알 수 없다. 종료는 캡틴·네비게이터가 직접 전환한다([POL-0002](POL-0002-study-status.md)) |

## 판정 규칙

- 등록 폼은 **무엇을 만드는지부터 묻고 날짜를 마지막에 받는다** — 제목·소개·주제·설명이 먼저, 마감일·
  정원·진행 시작일·채널 주소가 나중.
- **신청 폼이 저장돼 있어야 공개할 수 있다.** 폼 없이 공개하면 크루가 신청할 방법이 없다.
- 등록 후 변경 불가: 프로그램 연결(`studyProgramId`), 종류(`STUDY_KIND`).
- 정원·마감일은 모집 회차(`STUDY_RECRUITMENT`)에 저장되고, 나머지는 기수(`STUDY`)에 저장된다 —
  저장 위치는 백엔드 사정이고 등록 폼은 한 화면에서 함께 받는다.

## 미확정

- **이름 중복** — 스터디 이름은 겹치지 않게 운영한다고 들었다. 클럽 새 기수 제목을 프로그램 제목
  그대로 채우면 기수마다 같은 제목이 생긴다. 기수 표기를 붙일지, `STUDY.TITLE` 유니크 제약을 둘지
  결정 필요.
- **진행 일정 타입** — 지금은 자유 텍스트(`STUDY.SCHEDULE`). 기간 정렬·필터가 필요하면 `START_AT`/
  `END_AT` 로 받아야 한다.

## 백엔드와 어긋난 것

**아직 백엔드에 반영되지 않은 제안이다.**

| 무엇 | 지금 백엔드 | 기획 |
|---|---|---|
| `STUDY_DELIVERY_FORMAT` | 컬럼 있음, NOT NULL, 등록 시 `ONLINE` 하드코딩 | 받지 않는 값이라 컬럼 삭제 대상 |
| `STUDY.CAPACITY` | 기수 단위 정원 컬럼 있음 | 삭제 대상. 정원은 `STUDY_RECRUITMENT.RECRUITMENT_CAPACITY` 하나로 통일 |
| `STUDY.PUBLISH_AT` | 공개 예정 일시 컬럼 있음 | 삭제 대상. 예약 공개 없음 |
| `STUDY.SLUG` | `UUID.randomUUID()` 로 채움 | 삭제 대상. URL 은 `STUDY.ID` 사용 |
| `STUDY.START_AT`·`DISCORD_CHANNEL_URL`·`DRIVE_URL` | 컬럼은 있으나 등록 API 가 입력으로 받지 않음 | 등록·수정 폼에서 받도록 API 확장 필요 — [study/spec.md](../../../specs/study/spec.md) |
