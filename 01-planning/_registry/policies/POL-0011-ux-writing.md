# POL-0011 · UX 라이팅

> 시행일: 2026-11-16 · 적용: 사용자 사이트 · 운영 콘솔 전 화면
> 화면에 나오는 **말**을 정한다. 같은 상황을 화면마다 다르게 말하면 쓰는 사람이 매번 다시 읽는다.

## 1. 경계 — 이 문서가 다루지 않는 것

| 무엇 | 어디 |
|---|---|
| 창을 띄울지 토스트로 알릴지, 버튼 배치, 닫는 길 | [POL-0008](POL-0008-screen-rules.md) 「창과 알림」 |
| 거르는 드롭다운의 첫 줄, 표, 저장 중 표시 | [POL-0008](POL-0008-screen-rules.md) |
| 시각·날짜 표기 형식, 어느 시계로 보여주나 | [POL-0006](POL-0006-timezone.md) |
| 역할 이름이 무엇인가 (캡틴·네비게이터·크루) | [POL-0001](POL-0001-roles.md) |
| 스터디 상태 이름 (개설·진행 중·종료…) | [POL-0002](POL-0002-study-status.md) |

**이 문서는 그 자리에 들어갈 「어떤 단어를, 어떤 말끝으로」만 정한다.** 구조와 말이 부딪히면
**구조 쪽(POL-0008·0006)이 이긴다.**

---

## 2. 보이스 — 두 사이트가 다르게 말한다

**사용자 사이트와 운영 콘솔은 읽는 사람도, 처지도 다르다.** 하나로 통일하지 않는다.

| | 사용자 사이트 | 운영 콘솔 |
|---|---|---|
| 읽는 사람 | **크루** — 자원해서 온 사람 | **캡틴** — 일하러 온 사람 |
| 자세 | 같이 공부하자고 **청하는** 쪽 | 일을 **거드는** 쪽 |
| 요청 말끝 | **「~해 주세요」** | **「~하세요」** |
| 예 | 「닉네임을 입력해 주세요」 | 「제목을 입력하세요」 |

콘솔에서 「~해 주세요」를 쓰지 않는 이유는 **하루에 수십 번 보는 말**이기 때문이다. 매번 부탁받을
일이 아니다. 반대로 사용자 사이트에서 「~하세요」만 쓰면 지시하는 말이 된다.

### 공통으로 지키는 것

- **덜어낸다.** 없어도 뜻이 통하는 말은 뺀다 — 「정말로」 · 「한 번」 · 「성공적으로」 · 「현재」 · 「총」
- **차분하게.** 느낌표 · 감탄사 · 이모지를 쓰지 않는다. 경고도 사실만 담담히
- **가르치지 않는다.** 사용자가 틀린 것으로 몰지 않는다 — 「잘못된 입력입니다」가 아니라 「형식을 확인해 주세요」
- **사람을 2인칭으로 부르지 않는다** — 「귀하」 · 「당신」 · 「회원님」을 쓰지 않는다

## 3. 문장 규칙

### 3.1 훑는 자리는 명사형, 읽는 자리는 문장

화면은 읽는 곳이 아니라 **훑는 곳**이다. 제목 · 라벨 · 버튼 · 열 이름은 **명사형**으로 끝낸다.

| 자리 | 쓴다 | 쓰지 않는다 |
|---|---|---|
| 지면 제목 | 알림 발송 이력 | 알림을 발송한 이력입니다 |
| 칸 라벨 | 탈퇴 사유 | 탈퇴 사유를 선택합니다 |
| 버튼 | 스터디 등록 | 스터디를 등록하기 |
| 열 이름 | 디스코드 | 디스코드 연동 여부 |

**사용자에게 무엇을 해야 하는지 알리는 문장은 서술형이다** — 「참여 중단은 캡틴에게 문의해 주세요.」
예외 없이 명사형으로 밀면 「캡틴 문의」 같은 말이 나온다.

### 3.2 한 화면 안에서 말끝을 섞지 않는다

「~어요」와 「~습니다」가 한 창에 같이 있으면 두 사람이 쓴 글처럼 읽힌다.
**안내·결과 문장은 「~습니다」로 통일한다.**

| 쓴다 | 쓰지 않는다 |
|---|---|
| 5MB 이하 이미지만 첨부할 수 있습니다 | 이미지는 한 장에 5MB까지 붙일 수 있어요 |
| 이미지를 읽지 못했습니다 | 이미지를 읽지 못했어요 |

### 3.3 한 문장에 한 가지

둘을 전해야 하면 문장을 나눈다. **묻는 말을 먼저, 알아야 할 사실을 뒤에.**

- 쓰지 않는다 — 「날짜를 바꾸면 수정 중인 정보가 사라지니 주의하여 변경하시겠습니까?」
- 쓴다 — 「변경하시겠습니까? 수정 중인 정보는 저장되지 않습니다.」

### 3.4 결과는 짧게, 실패는 다음 행동까지

| 때 | 모양 | 예 |
|---|---|---|
| 성공 | 결과만 | 「저장되었습니다.」 |
| 성공 + 더 할 말 | 결과 + 사실 | 「변경 성공. 디스코드 권한은 별도로 변경해야 합니다.」 |
| 실패 | 사실 + 다음 행동 | 「권한을 바꾸지 못했습니다. 다시 시도해 주세요.」 |

**실패를 사과로 시작하지 않는다.** 무엇이 안 됐고 이제 뭘 하면 되는지가 먼저다.

### 3.5 되돌릴 수 없다는 말은 진짜 그럴 때만

「복구되지 않습니다」 · 「되돌릴 수 없습니다」는 **실제로 되돌릴 수 없는 동작에만** 쓴다.
참여 중단처럼 되살릴 수 있는 일에는 쓰지 않는다.

## 4. 용어

### 4.1 사람

| 쓴다 | 쓰지 않는다 | 왜 |
|---|---|---|
| **캡틴** | 운영진, 관리자, 어드민 | 「운영진」은 **누구를 찾아가야 하는지 가리키지 못한다** |
| **네비게이터** | 반장, 리더, 스터디장 | 현장에서 「반장」이라 불러도 화면 표기는 하나다 |
| **크루** | 참여자, 멤버, 수강생, 회원님 | |

**없는 역할을 지어내지 않는다.** 「해당 스터디 운영진」 같은 말은 찾아갈 데가 없다.
화면에 사람을 적기 전에 **그 역할이 POL-0001 에 있는지** 본다.

> 예외 — 약관·개인정보 처리방침의 「운영진」은 그 문서가 제2조에서 정의한 낱말이라 그대로 둔다.
> 소개·가이드에서 캡틴을 **설명하는** 자리(「커뮤니티를 운영하는 운영진」)도 부르는 이름이 아니라 둔다.

### 4.2 스터디

| 쓴다 | 쓰지 않는다 | 뜻 |
|---|---|---|
| **스터디** · **클럽** | 강의, 과정, 클래스 | 한 번 모집해 한 번 진행 / 기수를 이어 가는 것 |
| **기수** | 차수, 시즌 | 한 번의 운영 단위 |
| **반** | 분반, 그룹, 조 | 같은 기수 안에서 시간대로 나눈 묶음 |
| **회차** | 세션, 차시 | 한 번의 모임 |
| **카테고리** | 주제, 분야, 태그 | 2026-10 에 「주제」에서 되돌렸다 |

### 4.3 동작

| 쓴다 | 쓰지 않는다 | 뜻 |
|---|---|---|
| **등록** | 추가, 생성, 만들기 | 새로 만들어 확정 |
| **공개** / **비공개** | 노출, 게시, 오픈 | 사용자 사이트에 세운다 |
| **신청** | 지원, 접수, 등록 | 크루가 스터디에 넣는 것 |
| **참여 중단** | 탈퇴*, 제외, 강퇴 | 스터디에서 빠지는 것 (*탈퇴는 계정에만 쓴다) |
| **탈퇴** | 회원 해지, 계정 삭제 | **계정**을 지우는 것 |
| **연결** / **연결 해제** | 연동*, 링크 | 디스코드 계정 잇기 (*문서에서는 연동도 쓴다) |
| **재발송** | 재전송, 다시 보내기 | |

**「참여 중단」과 「탈퇴」를 섞지 않는다** — 하나는 스터디, 하나는 계정이다.

### 4.4 그 모듈에서만 쓰는 말

한 화면에서만 쓰는 도메인 용어는 여기 모으지 않고 **그 Story 의 PRD** 에서 관리한다.
다만 여기 있는 말과 부딪히면 **이 표가 이긴다.**

## 5. 자리별 규칙

### 5.1 버튼

- **동사 명사형.** 「저장」 · 「삭제」 · 「재발송」 · 「템플릿 추가」
- 「~하기」를 붙이지 않는다 — 「저장하기」 ✕
- **네 글자 안팎**이면 좋다. 길어지면 **그 동작이 모호하다는 신호**다
- **창에서 읽은 말과 누르는 말이 같아야 한다** — 창이 「재발송합니다」면 버튼도 「재발송」

> 버튼을 몇 개 둘지, 취소를 둘지는 [POL-0008](POL-0008-screen-rules.md) 소관이다.

### 5.2 입력 칸

| 요소 | 규칙 | 예 |
|---|---|---|
| 라벨 | 명사형, 짧게. 선택이면 **「(선택)」을 라벨에 붙인다** | 「이미지 첨부 (선택)」 |
| 자리표시 | **입력 예시**를 보여준다 | 「AI 논문 스터디」 |
| 도움말 | 한도·형식을 **보편적인 말**로 | 「최대 3장, 장당 5MB · PNG, JPG」 |
| 오류 | **무엇을 하면 되는지** | 「한글 20자(영문 40자) 이내로 입력하세요.」 |

- **자리표시에 꼭 알아야 할 정보를 넣지 않는다** — 입력하면 사라진다
- **오류에 책임을 돌리지 않는다** — 「잘못된 형식」 ✕ → 「형식을 확인해 주세요」

### 5.3 비어 있을 때

**「없다」는 사실만** 적는다. 사과하지 않고, 조건을 탓하지 않는다.

| 때 | 문구 |
|---|---|
| 아직 아무것도 없음 | 「아직 크루가 없습니다.」 · 「등록된 공지가 없습니다.」 |
| 거른 결과가 없음 | 「선택한 조건의 발송 이력이 없습니다.」 |
| 읽지 못함 | 「발송 이력을 불러오지 못했습니다. 다시 시도해 주세요.」 |

**「없음」과 「못 읽음」을 같은 말로 쓰지 않는다** — 운영자가 할 일이 다르다 (POL-0008).

### 5.4 토스트

- **한 문장.** 주어를 생략하고 결과만
- 성공 「~되었습니다」 · 실패 「~하지 못했습니다」
- **여러 건은 모아서 한 번** — 「9건 재발송에 성공했습니다. 실패: 3건」

## 6. 쓰지 않는 말

| 유형 | 쓰지 않는다 | 대신 |
|---|---|---|
| **AI 말투** | 「선택 · 3장까지, 한 장에 5MB」 | 「최대 3장, 장당 5MB」 |
| | 「눌러서 고르거나 끌어 놓기」 | 「클릭하거나 드래그하여 첨부」 |
| **서정적 표현** | 「지난 기록은 돌아오지 않습니다」 | 「이전 기록은 복구되지 않습니다」 |
| **모호한 때** | 「잠시 후」 · 「곧」 | 구체적인 값, 또는 돌아가는 표시 |
| **모호한 수** | 「여러 개」 · 「많은」 | 「N건」 · 「N명」 |
| **과장** | 「완벽하게」 · 「간편하게」 · 「스마트한」 | 사실만 |
| **감정 자극** | 「정말로」 · 「절대」 · 느낌표 | 담담하게 |
| **접은 개념** | 승인 대기 · 임박 · 오늘 마감 · 상시 모집 · 주제 | (쓰지 않는다) |

**「오늘 마감」을 운영 화면에 쓰지 않는다** — 신청을 재촉하는 말이라 운영자가 읽을 자리가 아니고,
이미 끝난 것으로도 읽힌다.

## 7. 고쳐 쓰기 예시

| 상황 | 쓰지 않는다 | 쓴다 |
|---|---|---|
| 저장 성공 | 성공적으로 저장이 완료되었습니다! | 저장되었습니다. |
| 권한 변경 | 권한을 캡틴으로 바꿨습니다. 디스코드 설정 변경은 운영자에게 요청해 주세요. | 변경 성공. 디스코드 권한은 별도로 변경해야 합니다. |
| 탈퇴 안내 | 같은 구글 계정으로 다시 가입할 수 있지만, 지난 기록은 돌아오지 않습니다. | 재가입은 가능하지만 이전 기록은 복구되지 않습니다. |
| 해제 차단 | 참여 중인 스터디가 있어 해제할 수 없어요. 해당 스터디 운영진에게 문의해 주세요. | 참여 중인 모든 스터디의 참여를 중단한 뒤 다시 시도해 주세요. 참여 중단은 캡틴에게 문의해 주세요. |
| 미루기 버튼 | 나중에 하기 | 스터디 먼저 둘러보기 |
| 첨부 안내 | 선택 · 3장까지, 한 장에 5MB · PNG · JPG · WEBP · GIF | 최대 3장, 장당 5MB · PNG, JPG, WEBP, GIF |

## 8. 쓰고 나서 보는 것

1. **없는 말을 쓰지 않았는가** — 역할·상태·단계가 정책에 실재하는가
2. **화면이 이미 말하고 있지 않은가** — 배지·버튼·열 이름이 말하면 글은 뺀다
3. **다른 화면은 뭐라고 부르는가** — 같은 값이면 같은 말
4. **이 사이트의 말끝인가** — 사용자 사이트 「~해 주세요」 / 콘솔 「~하세요」
5. **소리 내어 읽어도 어색하지 않은가**
