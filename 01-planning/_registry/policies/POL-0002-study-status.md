# POL-0002 · 스터디 상태

> 시행일: 2026-09-22 · 적용: 콘솔 스터디 목록·상세 · 사용자 사이트 스터디 목록·상세
> 백엔드 대응: [`docs/erd/STUDY.md`](../../../docs/erd/STUDY.md) (기수) · [`docs/erd/STUDY_RECRUITMENT.md`](../../../docs/erd/STUDY_RECRUITMENT.md) (모집 회차) · [`specs/study/spec.md`](../../../specs/study/spec.md)
>
> 백엔드 테이블이 2026-09 에 갈라졌다 — `STUDY_PROGRAM`(스터디 정체성) · `STUDY`(기수) · `STUDY_RECRUITMENT`(모집 회차).
> 아래 값은 전부 **기수(`STUDY`)** 의 것이다.

## 단위

| 단위 | 무엇 | 백엔드 |
|---|---|---|
| 스터디 | 「무엇을 하는 스터디인가」. 기수를 거듭해도 같은 것 | `STUDY_PROGRAM` |
| 기수 | 한 번 열리는 회차. 1기·2기… 정원·일정·상태가 여기 붙는다 | `STUDY` |
| 모집 | 기수 하나에 모집 회차가 여러 개일 수 있다(추가 모집). 정원·마감일·신청자 수는 **id 최대인 회차** 기준으로 판정한다 | `STUDY_RECRUITMENT` |

## 두 축으로 나눈다

STUDY_KIND(스터디/클럽)는 기수가 아니라 프로그램의 속성이라 여기서 다루지 않는다 — [POL-0003](POL-0003-study-fields.md).

| 축 | 값 | 정하는 주체 | 저장 |
|---|---|---|---|
| 라이프사이클 | `DRAFT` 작성 중 · `OPEN` 개설 · `ONGOING` 진행 중 · `ENDED` 종료 · `CLOSED` 운영 종료 | 사람(캡틴·네비게이터) + 일부 시스템 | `STUDY.STATUS` **(5단계, 저장)** |
| 모집 상태 | `RECRUITING` 모집중 · `RECRUIT_CLOSED` 모집마감 | 날짜·정원 | **저장하지 않는다 (매 조회 계산)** |

모집 상태는 `STATUS = OPEN` 일 때만 값이 있다. 그 밖에서는 `null` — 「마감됐다」가 아니라 **모집이라는
개념이 없다**. 진행중·종료는 모집 상태가 아니라 `STATUS`(`ONGOING`·`ENDED`)로 저장한다 — 날짜로
계산하지 않는다.

## 화면에 뜨는 말

| `STATUS` | 모집 상태 | 화면 표기 |
|---|---|---|
| `DRAFT` | (없음) | 미공개 — 콘솔에서만 보인다. 사용자 사이트 노출 없음 |
| `OPEN` | `RECRUITING` | 모집중 |
| `OPEN` | `RECRUIT_CLOSED` | 모집 마감 |
| `ONGOING` | (없음) | 진행중 |
| `ENDED` | (없음) | 종료 |
| `CLOSED` | (없음) | 운영 종료 (사용자 사이트에서는 「종료」에 묶는다) |

콘솔 단계 이름에는 **「공개」를 쓰지 않는다** — `DRAFT` 를 벗어난 네 단계(`OPEN`·`ONGOING`·`ENDED`·
`CLOSED`) 는 전부 공개 상태이기 때문이다. 공개 여부는 아래(`STATUS != DRAFT`)가, 신청 가능 여부는
모집 상태가 말한다.

## 공개 여부

별도 플래그(`IS_HIDDEN`)를 두지 않는다. **판정은 `STATUS != DRAFT` 하나다.** 모집 시작 일자
(`STUDY_RECRUITMENT.START_AT`)로 판정하지 않는다 — 캡틴이 모집을 시작하면 `STATUS: DRAFT → OPEN`
과 `START_AT` 채움이 항상 같이 일어나 두 값이 이론상 늘 일치하지만, 필드가 둘이면 한쪽만 바뀌는
버그가 생길 여지가 있다(공개 취소가 `STATUS` 만 되돌리고 `START_AT` 은 못 지우면, `START_AT` 기준
판정은 여전히 공개로 남는다). `STATUS` 하나만 보면 이 동기화 문제가 없다. 예약 공개는 없다.

> 지금 등록 API가 `START_AT` 을 `now()` 로 채우는 것도 고쳐야 할 별도 버그다(등록 직후 미공개로
> 두려는 기획과 어긋난다) — 자세한 내용은 [STUDY.md](../../../docs/erd/STUDY.md#공개-여부) 참고.
> `STATUS` 기준으로 판정을 옮기면 이 버그가 공개 여부에는 더 이상 영향을 주지 않지만, `START_AT` 자체는
> 여전히 잘못된 값이라 데이터 정확성을 위해 별도로 고쳐야 한다.

## 판정 규칙

- **모집 마감은 자동**이다 — 마감일이 지나거나 정원이 차면 그 순간부터 마감(`RECRUIT_CLOSED`)으로
  보인다. 마감일은 등록 폼에서 필수로 받는 값이라 늘 계산할 수 있다. 상시 모집은 없다.
- **개설 → 진행중은 사람이 한다.** 네비게이터가 첫 미팅([STUDY_MEETING](../../../docs/erd/STUDY_MEETING.md))을
  등록하면 전환된다.
- **진행중 → 종료는 사람 또는 시스템이다.** 네비게이터가 종료 처리하거나, 마지막 미팅으로부터 N주가
  지나면 자동 전환된다(N 미정).
- **종료 → 운영 종료는 캡틴만, 항상 수동이다.** 시스템이 디스코드 채널이 실제로 지워졌는지 검증하지
  않는다 — 자동 연동이 불가능한 이유는 [STUDY.md](../../../docs/erd/STUDY.md#채널-삭제와-closed) 참고.
  같은 이유로 **그 프로그램에서 가장 최신(`STUDY.ID` 최댓값) 기수만** 운영 종료로 전환할 수 있다 —
  지나간 기수는 채널을 다음 기수에 넘겨주고 역할이 끝난 것이라 `ENDED` 에 영구히 남는다.
- 정원 도달은 **도달**이 마감이다 — 초과까지 기다리지 않는다.
- 진행 시작·종료일(`START_AT`/`END_AT`)은 화면에 보이는 값일 뿐 상태를 바꾸지 않는다 — 상태는 위
  전이로만 바뀐다.
- 공개하려면 신청 폼이 저장돼 있어야 한다 ([POL-0003](POL-0003-study-fields.md)).

## 미확정

- **공개 취소(`OPEN → DRAFT`) 조건** — ERD 다이어그램은 「신청 0건일 때만」이고, 프로토타입은 조건
  없이 언제나 허용한다. 신청이 있는 스터디를 내리면 신청자는 어떻게 되는지 정하지 못했다
  ([study/spec.md](../../../specs/study/spec.md#스터디-공개--공개-취소)).
- **종료(`ENDED`) 자동 전환의 N주** — 마지막 미팅으로부터 몇 주 뒤 자동 종료할지 미정.
- **운영 종료 이후 재개** — `CLOSED` 인 프로그램에 새 기수(새 채널)를 만드는 것은 막지 않는다. 형제
  기수의 `STATUS` 는 새 기수 생성 조건이 아니다.

## 백엔드와 어긋난 것

**아직 백엔드에 반영되지 않은 제안이다** — 이 정책은 콘솔·사용자 사이트 프로토타입 기준이고, 지금
백엔드 코드는 아래 왼쪽 열 그대로다.

| 무엇 | 지금 백엔드 | 기획 |
|---|---|---|
| `STATUS` 값 | 3값(`DRAFT`/`OPEN`/`CLOSED`) | **5값** — `ONGOING`·`ENDED` 추가. 진행중·종료를 모집 상태가 아니라 라이프사이클로 저장 |
| `STUDY_KIND` | `STUDY` 컬럼(기수 단위) | `STUDY_PROGRAM` 으로 이동(프로그램 단위). 한 번 정하면 변경 불가 — [POL-0003](POL-0003-study-fields.md) |
| 공개 여부 | `IS_HIDDEN` 플래그. 등록 시 `START_AT=now` 를 채움 | `IS_HIDDEN` 삭제. 공개 = `STATUS != DRAFT`. 등록 직후는 항상 `DRAFT`(미공개) — 등록 API가 `START_AT=now` 채우는 것도 별도로 고쳐야 함 |
| 상시 모집 | `RECRUIT_DEADLINE_AT` NULL 허용 | NOT NULL — 상시 모집 없음. 이어지는 참여는 클럽의 기수 이월로 표현 |
| 완료 전환 | 「운영자 종료 또는 `END_AT` 경과」로 `CLOSED` | `END_AT` 경과로 자동 종료하지 않는다. `ONGOING → ENDED` 만 N주 경과로 자동, `ENDED → CLOSED` 는 캡틴 수동 확인만 |
| 모집 회차 | 1개로 가정 | 여러 개 허용(추가 모집). id 최대인 회차 기준으로 판정 — [study-recruit-status](../../../specs/study-recruit-status/spec.md) |
