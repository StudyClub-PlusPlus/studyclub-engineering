# 이 레포에서 일하기 전에 (에이전트용)

> 사람용 안내는 [`docs/onboarding/`](../docs/onboarding/README.md). 이 파일은 **에이전트가 일을 시작하기 전에 읽는 한 장**이다.
> 구조가 바뀌면 리드가 고친다.

## 지도

| 어디 | 무엇 |
|---|---|
| (채우기) `apps/` · `backend/` … | (채우기) |
| `specs/<기능>/` | 기능 하나의 계약 — 코드와 같이 고친다 |
| `.agents/tasks/ops/` · `.agents/tasks/cs/` | 반복 운영 작업 · 고객 문의 대응 절차 |
| `docs/` | 사람이 읽는 것 전부 — [`docs/README.md`](../docs/README.md) |

## 하지 말 것

- 기본 브랜치에 직접 push
- prod DB 쓰기 · prod 백오피스 화면 캡처 (화면은 stage, 개인정보는 가린다)
- 문서·코드에 시크릿 값 (자리만 두고 "담당자에게 요청")
- (채우기 — 이 레포 고유 금지)

## 자주 쓰는 명령

```bash
# (채우기) 테스트 · 빌드 · 로컬 실행
```

## 무엇을 어디에 쓰나

| 이런 일이 생기면 | 여기에 | 언제 |
|---|---|---|
| 팀이 알아야 할 결정 · 팀에 물을 것 | `docs/share/YYYY-MM-DD-<주제>.md` | 그 PR 안에서 |
| 결정이 굳었다 (2주+ 그대로 쓰임) | `docs/adr/NNNN-<주제>.md` | 굳었을 때 |
| prod 사고를 고쳤다 | `docs/incidents/YYYY-MM-DD-<요약>.md` | 72시간 안 |
| 같은 운영 작업을 두 번째 한다 | `.agents/tasks/ops/<작업>.md` | 두 번째 할 때 |
| 같은 고객 문의가 두 번 왔다 | `.agents/tasks/cs/<문의 유형>.md` | 두 번째 올 때 |
| 일을 끝냈다 | `docs/roadmap/tasks.md` 완료일 | 머지한 날 |
| 화면이 바뀌었다 | PR 「화면 변경 근거」에 캡처 — 월말 `docs/releases/` 가 모아 간다 | 그 PR 안에서 |

결정·사고·두 번째 운영 작업을 만나면 **같은 PR 에 넣을지 사람에게 먼저 묻는다.**
