# 화면 문구 · 표기 규칙

화면에 보이는 모든 글자(제목·본문·버튼·placeholder·빈 상태·에러·메타 title·description·JSON-LD)에 적용한다.
코드 주석·개발 문서·테스트 이름은 대상이 아니다.

## 1. 줄표(—)를 쓰지 않는다

AI 가 쓴 문구의 제일 흔한 표시가 **줄표**(em dash `—`, en dash `–`, 한글 `ㅡ`)다. 읽는 사람이 바로 알아챈다.

| 줄표를 쓰고 싶은 자리 | 대신 |
|---|---|
| 앞말을 풀어 쓴다 (`킥오프 참여까지 — 단계별 안내`) | 문장을 둘로 나눈다 · 쉼표 |
| 항목 이름과 설명 (`경고 — 이메일로 시정 요구`) | 쌍점 (`경고: 이메일로 시정 요구`) |
| 브랜드 타이틀 (`스터디클럽 — 무료 스터디`) | `스터디클럽 \| 무료 스터디` |
| 괄호처럼 끼워 넣기 (`세팅 — 모집, 킥오프 — 을 도와`) | 괄호 `세팅(모집, 킥오프)을 도와` |
| 범위 (`2–20자`, `10–15명`) | `2~20자` · `2 to 20 characters` |
| 표의 빈 값 | `-` 또는 `없음` |

**자기검사: 0건이어야 한다** (문구를 고친 PR 마다):

```bash
grep -rnE "—|–|ㅡ" --include="*.tsx" --include="*.ts" --include="*.json" frontend/apps/core-front/src \
  | grep -vE ":[0-9]+:\s*(//|\*|/\*|\{/\*)" | grep -vE "//.*(—|–)"
```

## 2. 자간 벌린 대문자 라벨(킥커)을 쓰지 않는다

`LIFESTYLE` · `CAREER` 처럼 `uppercase tracking-[0.14em]` 을 준 작은 라벨은 한국어 화면에서 어색하고,
필터 칩(「라이프스타일」)과 이름이 달라 같은 개념이 두 이름이 된다.

- 카테고리 이름은 **필터 칩과 같은 표기**를 쓴다 (`CATEGORY_DISPLAY`, `packages/ui` 의 `categoryMeta().label`)
- 라벨은 `text-xs font-semibold` 정도로. 대문자·자간 없이

## 3. 한 개념은 한 이름

- 역할: **크루**(참여) · **네비게이터**(스터디 하나를 이끈다) · **캡틴**(운영진). 「반장·부반장」은 쓰지 않는다
- 서비스 이름: **스터디클럽** / **StudyClub**. `++` 를 붙이지 않는다
- 버튼 이름은 도착할 화면 이름과 같게

## 4. 비용·운영 형태를 단정하지 않는다

「무료」「100% 자원봉사」「수익 전액 기부」「비영리」처럼 **나중에 바뀔 수 있는 운영 조건**을 화면·메타 문구에 쓰지 않는다.
유료화·후원 모델이 생기는 순간 이미 나간 문구가 약속이 된다. 약관의 책임 조항처럼 법적 문구는 법무 검토로만 바꾼다.

## 5. 숫자는 출처가 있을 때만

회원 수 같은 숫자는 `packages/mock` 의 `site.community.member_count` 하나에서 읽는다. 문구에 숫자를 따로 박지 않는다
(박혀 있으면 바뀔 때 한 곳만 고쳐진다). 천 단위는 `toLocaleString()`.
