# 담당 캡틴은 「등록한 사람」과 따로 저장하고, 백오피스 신청자 탭에서 바꾼다

## 미리 알아야 할 것

- **캡틴**: 운영진 계정(`ACCOUNT.SYSTEM_ROLE=ADMIN`). 백오피스(운영 콘솔)에 들어간다.
- **담당 캡틴**: 스터디 하나를 책임지는 캡틴. 신청 폼 수정 · 참여 중단 · 사용자 사이트 일정 관리처럼 그 사람만 하는 일이 있다.
- **네비게이터**: 반마다 서는 반장(`STUDY_PARTICIPANT.PARTICIPANT_ROLE=LEADER`). 캡틴이 아니다.
- **명부**(`STUDY_PARTICIPANT`): 그 스터디에 **참여한** 사람 목록. 출석 · 정원 · 크루 명단이 모두 이 표를 읽는다.
- **`STUDY.CREATED_BY`**: 스터디를 **등록한** 계정. 지금까지 담당 캡틴 판정에 이 칸을 썼다.

## 한 줄 요약

담당 캡틴을 새 칸 **`STUDY.OWNER_CAPTAIN_ID`** 에 저장한다. 스터디를 만들면 만든 캡틴이 들어가고, 백오피스 **신청자 탭**에서 **캡틴 누구나** 다른 캡틴으로 바꿀 수 있다. `CREATED_BY` 는 「등록한 사람」 기록으로만 남는다.

## 왜 — 지금 뭐가 문제인가

교실에 비유하면 `CREATED_BY` 는 **반을 개설한 사람**이고, 담당 캡틴은 **담임**이다. 처음엔 개설한 사람이 담임을 맡지만, 담임은 바뀔 수 있다. 개설한 사람은 바뀌지 않는다.

지금은 두 개념을 `CREATED_BY` 한 칸으로 판정한다. 그래서 다른 캡틴에게 스터디를 넘길 방법이 없다. 등록 기록을 고치면 「누가 등록했나」라는 사실이 사라진다.

## 검토하고 고르지 않은 안 — 명부에 담당 캡틴 표시

명부 행에 「담당 캡틴」 표시를 붙이는 안도 봤다. 하지만 명부 행이 있다는 것은 곧 **참여한다**는 뜻이다. 담당 캡틴은 참여하지 않고 운영만 할 수도 있다(10-14 결정). 참여하지 않으면 행이 없으니 표시를 붙일 곳이 없다. 행을 억지로 만들면 정원 · 출석부 · 인원 수가 모두 그 행을 걸러야 한다. 10-14 에 원복한 안과 같다.

**개수로 나눈다**: 스터디당 한 명인 담당 캡틴은 `STUDY` 에, 반마다 있는 네비게이터와 참여 여부는 명부에 둔다.

| 상황 | `STUDY.OWNER_CAPTAIN_ID` | 명부 행 |
|---|---|---|
| 담당 캡틴이 크루로도 참여 | 나 | 있음 (`MEMBER`) — 정원 · 출석에 들어간다 |
| 담당 캡틴이 운영만 | 나 | 없음 |

## 정해진 것

| 무엇 | 결정 |
|---|---|
| 몇 명 | 스터디당 **한 명** |
| 처음 값 | 스터디를 만든 캡틴 |
| 바꾸는 곳 | 백오피스 스터디 운영 → **신청자 탭** 맨 위 「담당 캡틴」 칸. 명단 행의 역할 드롭다운이 아니다 |
| 누가 바꾸나 | **캡틴이면 누구나** |
| 누구로 바꿀 수 있나 | **캡틴(ADMIN) 계정만.** 명부에 있는지와 상관없다 |
| 캡틴 권한을 내릴 때 | 진행 중인 스터디(끝나지 않은 스터디)의 담당 캡틴이면 **막는다.** 「담당 캡틴을 먼저 바꿔 주세요」와 스터디 이름을 보여 준다 |
| 끝난 스터디(`ENDED` · `CLOSED`) | 막지 않는다. 권한을 내릴 때 담당 캡틴 칸을 비운다 |
| 계정 탈퇴 | 담당 캡틴 칸을 비운다 (지금 `CREATED_BY` 를 비우는 것과 같다) |
| 담당 캡틴이 없는 스터디 | 담당 캡틴만 하는 일을 **캡틴 누구나** 한다 (지금 규칙 그대로) |
| `CREATED_BY` | 「등록한 사람」 기록. 백오피스 스터디 목록 「작성자」 열이 쓴다. 권한 판정에는 쓰지 않는다 |
| 기존 데이터 | 마이그레이션이 `OWNER_CAPTAIN_ID` 를 `CREATED_BY` 값으로 채운다. 오늘과 똑같이 동작한다 |

## 그래서 나는 뭘 해야 하나

- **기획**: 신청자 탭 담당 캡틴 칸의 문구와 위치를 playground 프로토에서 확인한다.
- **백엔드**: `Study.isCreatedBy` 를 `isOwnedBy` 로 바꾸고, `StudyCaptainGuard` 의 판정이 `OWNER_CAPTAIN_ID` 를 보게 한다. 변경 API 와 권한 해제 막기(`RoleChangeBlockedReason.OWNS_STUDY`)를 더한다.
- **프론트**: 백오피스 회원 목록은 막힌 사유를 이미 받아 버튼을 잠근다 — 새 사유의 문구만 더한다.
