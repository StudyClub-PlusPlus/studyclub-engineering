# 캡틴 위에 최고 관리자 — 캡틴 내리기는 최고 관리자만

## 미리 알아야 할 것

- **캡틴**: 운영진(`ADMIN`)이다. 백오피스에 들어올 수 있는 사람은 캡틴뿐이다.
- **최고 관리자**: 서버 설정 `SUPER_ADMIN_EMAILS`(콤마로 여러 명)에 이메일이 적힌 사람이다. 화면에서는 정할 수 없고, 서버 설정을 고쳐 다시 배포해야 바뀐다.

비유: 관리실 열쇠(캡틴)는 캡틴끼리 나눠 줄 수 있지만, 열쇠를 회수하는 일은 건물주(최고 관리자)만 한다. 건물주 명단은 관리실이 아니라 등기부(서버 설정)에 있다.

## 한 줄 요약

캡틴을 크루로 내리는 것은 최고 관리자만 할 수 있고, 최고 관리자는 화면 · API 로 내릴 수 없다. 크루를 캡틴으로 올리는 것은 지금처럼 캡틴 누구나 한다.

## 왜

- 지금은 캡틴이 다른 캡틴을 내릴 수 있어서, 운영진끼리 서로를 내리는 일을 막을 장치가 없다.
- 캡틴이 0명이 되면 복구 길이 DB 직접 수정뿐이었다(2026-10-10 결정). 이제는 서버 설정을 고쳐 다시 배포하면 그 사람이 부팅 때 캡틴이 된다.
- 유니버스의 다른 서비스 백오피스와 같은 규칙(청사진 super-admin)이다.

## 바뀐 것

| 무엇 | 전 | 후 |
|---|---|---|
| 캡틴이 다른 캡틴을 크루로 내리기 | 200 (본인 · 마지막 캡틴 · 진행 중 담당은 409) | 최고 관리자만 200, 아니면 403 `NOT_SUPER_ADMIN` |
| 최고 관리자인 캡틴을 내리기 | 해당 없음 | 403 `SUPER_ADMIN_LOCKED` |
| 크루를 캡틴으로 올리기 | 캡틴 누구나 | 그대로 |
| 회원 목록 | 권한 배지 | 최고 관리자 줄에 「최고 관리자」 배지, 내릴 수 없는 캡틴 줄은 배지가 잠기고 이유 툴팁 |
| 첫 캡틴 · 잠금 복구 | DB 에서 직접 `SYSTEM_ROLE=ADMIN` | 서버 설정에 이메일을 넣고 재배포 (가입한 계정이어야 한다) |
