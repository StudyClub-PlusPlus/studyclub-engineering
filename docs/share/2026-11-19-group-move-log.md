# 반 이동을 기록한다 — 네비게이터가 「어느 반에서 언제 왔나」를 출석부에서 본다

## 미리 알아야 할 것

- **반**(`STUDY_GROUP`): 한 스터디 안의 분반. 반마다 회차와 출석부가 따로 있다.
- **명부**(`STUDY_PARTICIPANT`): 스터디에 참여한 사람의 목록. 행 하나가 「이 사람은 지금 이 반」을 뜻한다.
- **반 이동**: 캡틴이 백오피스 신청자 탭에서 크루의 반을 바꾸는 일 (`PATCH /api/admin/studies/{id}/participants`). 지금은 명부 행의 반 칸 하나만 바뀐다.
- **네비게이터**: 반마다 서는 반장(`LEADER`). 사용자 사이트 「스터디 일정 › 출석」에서 자기 반 출석부를 본다.
- **캡틴**: 운영진(`ADMIN`). 백오피스 출석 탭에서 모든 반 출석부를 본다.
- **참여 중단**: 크루가 스터디에서 빠진 상태(`WITHDRAWN`). 출석률은 빠진 시각(`LEFT_AT`)까지만 센다.

## 한 줄 요약

반을 옮길 때마다 **새 표 `STUDY_PARTICIPANT_GROUP_MOVE` 에 한 줄**(옛 반 · 새 반 이름, 옮긴 시각, 옮긴 캡틴)을 남긴다. 네비게이터와 캡틴은 출석부에서 「A반에서 이동 · 11/10」을 보고, 새 반 출석부에서 **옛 반 기록을 「A반」 표시와 함께** 본다. **개인 출석률은 있었던 반을 모두 합산**하고, **반 평균은 그 반에서 기록된 것만** 센다.

## 왜 — 지금 뭐가 문제인가

반을 합치면 캡틴이 A반 크루를 B반으로 옮기고, 빈 A반을 지운다. 그런데 반 이동은 **아무 기록도 남기지 않는다.** 명부 행의 반 칸이 A에서 B로 바뀔 뿐이다.

그래서 B반 네비게이터 출석부에는 그 크루가 처음부터 B반이었던 것처럼 보인다. 어디서 왔는지, 언제부터 왔는지 알 길이 없다. A반을 지우면 「A반」이라는 이름까지 사라진다.

출석률도 어긋난다. 계산기는 **지금 반의 회차**만 본다. 그래서 A반에서 한 출석은 숫자에서 빠지고, A반 출석부에서는 그 크루가 아예 사라진다.

비유하면 학교에서 전학생이 왔는데 생활기록부에 「전학 옴」 한 줄이 없는 상태다. 담임은 이 학생이 언제 어느 학교에서 왔는지 모르고, 전 학교 출석부에서는 이름이 지워졌다.

## 검토하고 고르지 않은 안 — 운영 감사 로그(`ADMIN_AUDIT_LOG`)에 남기기

액션 하나(`GROUP_CHANGE`)만 더하면 되니 작업은 더 적다. 하지만 고르지 않았다.

- 감사 로그에는 캡틴 접속 IP와 「누가 누구의 이메일을 봤나」가 함께 있다. 지금은 남기기만 하고 어떤 화면도 읽지 않는다. 네비게이터 출석부가 이 표를 읽게 되면 민감한 기록과 제품 화면의 경계가 무너진다.
- 감사 로그의 보관 기한은 개인정보 정책으로 정한다(1~3년, 설정으로 바뀜). 정책이 바뀌면 출석부 표시도 같이 바뀐다.
- `BEFORE/AFTER` 두 칸에 반 이름을 넣으면 반 ID 가 남지 않는다. 출석률을 반별로 나눠 세려면 반 ID 가 필요하다.

## 정해진 것 (2026-11-19)

| 무엇 | 결정 |
|---|---|
| 남기는 곳 | 새 표 `STUDY_PARTICIPANT_GROUP_MOVE` — [ERD](../erd/STUDY_PARTICIPANT_GROUP_MOVE.md) |
| 남기는 때 | 반이 실제로 바뀐 명부 행마다 한 줄. 반 이동과 **같은 트랜잭션**이다. 기록이 실패하면 이동도 취소된다 |
| 남기는 값 | 옛 반 · 새 반의 ID 와 **그때 이름**, 옮긴 시각, 옮긴 캡틴 계정 ID |
| 반을 지우면 | 이 기록은 지우지 않는다. 이름을 복사해 두었으므로 「A반에서 이동」이 그대로 보인다 |
| 누가 보나 | **네비게이터와 캡틴만.** 크루가 출석부를 열면 이동 표시도 옮겨 간 사람 줄도 받지 않는다 |
| 옮긴 캡틴 | 기록은 하지만 **어느 화면에도 내지 않는다** |
| 옛 반 출석부 | **참여 중단처럼 다룬다.** 옛 반 출석부에 흐린 줄로 남고 「B반으로 이동」 칩이 붙는다. 이동 전 칸은 그대로, 이동 뒤 칸은 「—」 |
| 새 반 출석부 | **옛 반 기록을 가져와 보여 준다.** 출석 행은 옛 반 회차에 그대로 두고, 화면에서만 같은 **회차 번호**의 새 반 칸에 놓는다. 그 칸에는 「A반」 표시를 붙이고 흐리게, 고칠 수 없게 그린다. 새 반에 그 번호 회차가 없으면 줄 맨 앞 「A반 기록」 묶음에 따로 보인다 |
| 개인 출석률 (출석부 줄 · 내 스터디 · 완주 점수판) | **그 사람이 있었던 모든 반의 구간을 합산한다.** 옛 반 1~5회 5/5 + 새 반 6~10회 3/5 = 8/10. 반을 옮겨도 숫자가 이어진다 |
| 반 평균 출석률 | **그 반에서 기록된 것만** 센다. 가져온 칸은 넣지 않는다 — 넣으면 한 출석이 두 반에서 세진다 |
| 스터디 전체 · 대시보드 출석률 | 한 사람의 반별 구간을 각각 그 반에서 센다. 한 회차를 두 번 세지 않는다. 반을 옮기지 않은 경우와 숫자가 같다 |
| 과거 이동 | 기록이 없어 되살리지 못한다. 배포한 날부터 쌓인다 |

출석 행을 새 반으로 **옮겨 적지 않는** 이유: 옛 반 출석부의 기록이 사라지고, 새 반 회차가 옛 반보다 적으면 옮길 자리가 없다. 화면에서만 가져오면 원래 기록이 바뀌지 않는다. 옛 반은 출석 기록이 남아 있어 지금처럼 지울 수 없다 — 기록이 끊기지 않는다.

예 — 수아가 A반 1~5회에 모두 출석하고 6회차에 B반으로 옮겨 6~10회 중 3번 출석했다:

| 숫자 | 값 |
|---|---|
| B반 출석부 수아 줄 | 1~5회 칸에 A반 기록(「A반」 표시), 6~10회는 B반 기록. 출석률 **80%** (A반 포함) |
| A반 출석부 | 수아는 흐린 줄 + 「B반으로 이동」. 1~5회 칸은 그대로 |
| A반 평균에 들어가는 수아 몫 | 5/5 |
| B반 평균에 들어가는 수아 몫 | 3/5 |
| 스터디 전체에 들어가는 수아 몫 | 8/10 |

## 해석 — 다르면 알려 달라

결정에 적히지 않아 아래처럼 정했다. 다르면 스펙을 고친다.

1. **크루가 출석부를 열면** 다른 사람의 「A반」 표시 칸과 「A반 기록」 묶음을 받지 않는다 (이동 기록은 네비게이터 · 캡틴만 본다). 출석률 숫자는 같은 값(합산)을 받는다.
2. **가져온 칸은 새 반에서 고칠 수 없다.** 틀렸으면 캡틴이 백오피스에서 옛 반 출석부를 고친다.
3. [NEEDS CLARIFICATION] **크루 본인 「내 스터디」 회차 격자** — 출석률은 합산이지만, 격자에 옛 반 회차를 함께 그릴지는 정하지 않았다. 지금은 지금 반 회차만 그린다.

## 이전 결정과 달라진 것 (같은 날)

처음에는 「옮겨 온 크루는 새 반에 들어온 시각부터 출석률을 센다」였다. 그러면 반을 옮길 때마다 개인 출석률이 새로 시작하고, 늦게 옮긴 크루는 분모가 작아 숫자가 크게 흔들린다. 완주 점수판도 같은 회차를 보므로 불공정해진다. 그래서 **개인 숫자는 합산, 반 숫자는 구간**으로 나눴다.

## 그래서 나는 뭘 해야 하나

- **기획**: 위 「해석」 세 개를 확인한다. 출석부 이동 표시 · 「A반」 칸 · 「A반 기록」 묶음의 문구와 위치를 playground 프로토에서 확인한다.
- **백엔드**: 표를 만들고(`V65` — `V60` 은 다른 PR 이 먼저 썼다), `AdminStudyParticipantService` 의 반 이동 단계에서 한 줄씩 쓴다 (여기까지 됨). `AttendanceRateCalculator` 를 「반별 구간」으로 바꾸고 개인 = 구간 합산, 반 평균 = 그 반 구간으로 나눈다. 명부 조회에 가져온 칸(`recordedGroupName` · `otherGroupAttendances`)을 붙이고, 가져온 칸 저장은 막는다.
- **프론트**: core-front · back-office-front 출석부에 이동 표시 · 가져온 칸 · 옮겨 간 줄을 그린다. 크루가 보는 화면에는 이 값이 오지 않는다.
