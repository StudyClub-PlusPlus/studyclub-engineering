# 내 스터디는 프로필 시간대로 보고 입력한다 · 모집 화면은 유지

## 미리 알아야 할 것

프로필 시간대는 회원이 가입하거나 마이페이지에서 고른 지역이다. 반 시간대는 해당 반의 운영 기준 지역이다.
같은 모임도 서울 시계와 토론토 시계에는 서로 다른 시각으로 보인다. 벽시계를 바꿔 보는 것처럼, 표시 지역을 바꿔도 모임 자체가 이동하지는 않는다.

## 정해진 것

- 사용자 사이트의 내 스터디 카드·주간 일정·회차 일정·출석표·상단 정규 운영 시간은 프로필 시간대를 따른다. 프로필 값이 없거나 유효하지 않으면 브라우저, 그다음 서울을 쓴다.
- 조회 화면의 한국/미국 서부 전환 버튼을 없앤다. 지역명과 시간대 약칭을 함께 표시한다.
- 네비게이터의 기존 회차 표는 프로필 시간대로 시작한다. 서울·뉴욕/토론토·밴쿠버·LA로 전환한 뒤 현재 보이는 칸을 직접 수정하고 저장한다. 별도의 수정 버튼은 추가하지 않는다.
- 회차 추가 창은 표에서 임시로 선택한 지역과 관계없이 프로필 시간대로 열린다. 반복 요일·시각·종료일도 입력 지역 기준이다. 서머타임 전환 뒤에도 입력한 지역의 시각을 유지한다.
- 저장할 때는 협정 세계시(UTC)로 변환한다. 시간대만 전환하거나 제목만 수정하면 기존 모임 시각을 유지한다. 출석·킥오프 순서·하루 한 회차 판정은 반의 날짜 기준을 유지한다.
- 상단 정규 시간은 가까운 예정 정규 회차 날짜의 시차로 환산한다. 예정 회차가 없으면 마지막 정규 회차, 회차가 없으면 오늘을 기준으로 한다. 옆 안내에는 원래 반 기준과 서머타임 안내 두 문장만 둔다.
- 밴쿠버는 2026년 3월 8일 마지막 봄 전환 이후 연중 UTC−7(PCT)을 적용한다. LA는 날짜에 따라 여름 PDT·겨울 PST를 쓴다. 두 지역을 합치지 않는다.

## 10-31 리뷰 반영

- 반복 입력이 내 달력에서는 31일이어도 반 달력에서는 32일에 걸칠 수 있다. 실제로 추가할 회차를 반 날짜로도 검사하고, 넘으면 추가 전에 줄여야 할 종료일을 안내한다. 임의로 회차를 빼지 않는다.
- 기존 날짜·시각을 지웠다가 똑같이 다시 입력하면 원래 모임 순간을 유지한다. 서머타임 종료일의 두 번째 01:30이 첫 번째 01:30으로 바뀌지 않는다.
- 새로 입력한 시각이 두 번 존재하는 날짜에만 시계 전환 전/후를 선택한다. 선택한 모임 순간은 미리보기·추가·수정·저장에 동일하게 사용한다.

## 이번에 유지하는 것

실제 사용자 사이트의 모집 목록·상세 시간은 기존 그대로 둔다. 현재 서버 응답의 일정 문구와 KST/PST/BOTH 분류만으로는 모든 일정의 기준 지역을 명확히 구분하기 어렵다. 시작 예정일을 확정된 첫 모임 시각으로 가정하지 않는다.

Playground의 별도 확정 일정 예시는 검토용으로만 남는다. 실제 운영 콘솔의 일정 입력·출석 화면은 이번 적용 범위에 포함하지 않는다.

## 그래서 나는 뭘 해야 하나

- 기획·디자인: 사용자 사이트의 시간 기준을 위 규칙과 [POL-0006](../../01-planning/_registry/policies/POL-0006-timezone.md)으로 확인한다.
- 프론트 개발: 프로필 시간대와 저장된 모임 시각을 구분한다. 임시 시간대 선택으로 프로필이나 반 설정을 덮어쓰지 않는다.
- 검수: 서머타임 전후, 지역 간 날짜·요일 변경, 밴쿠버와 LA의 겨울 한 시간 차이를 확인한다.
