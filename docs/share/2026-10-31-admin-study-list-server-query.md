# 스터디 목록은 모든 검색·필터·정렬을 서버에서 처리한다

## 미리 알아야 할 것

페이지 조회는 조건에 맞는 목록 중 화면에 필요한 20개만 받는 방식이다. 전체 책을 옮겨 놓고 20권을 고르는 대신, 도서관에 검색 조건과 필요한 순서를 전달하는 것과 같다.

기존 목록은 일부 조건에서 100건씩 전체 자료를 받았다. 요청 사이 삭제로 항목이 빠질 수 있었고, 10,000건을 넘으면 조회가 실패했다.

## 결정

- 제목·한 줄 소개 검색, 신청 폼 유무, 모든 필터와 열별 정렬을 관리자 목록 API에 전달한다. 서버는 DB에서 조건·정렬·페이지를 적용한다.
- 일반 목록의 기본 순서는 모집중 먼저, 마감 시각이 빠른 순이다. 대시보드 진입 조건과 열별 정렬 기능은 유지한다.
- 목록의 모집 「마감」은 모집중이 아닌 전체 상태다. 작성 중·진행 중·종료·운영 종료도 포함한다. 상태 「개설」을 함께 선택하면 모집이 마감된 개설 기수만 포함한다.
- 기존 공통 `RECRUIT_CLOSED`는 개설 상태의 모집 마감을 뜻한다. 이 의미는 유지하고, 목록에 별도 `recruitFilter=NOT_RECRUITING`을 사용한다.
- 모집 판정은 기존 스터디 코드의 최신 모집 회차·신청서 수 기준을 유지한다. 모집 보드와 전체 보기는 같은 조회·정렬을 사용한다.

## 적용 범위

실제 백오피스 목록과 대시보드의 스터디 보드에 적용한다. Playground는 mock 화면을 유지한다. 공개 사이트의 모집 정책과 신청 가능 여부는 변경하지 않는다.

페이지 이동 사이의 추가·삭제까지 고정하는 기능은 아니다. 상세 계약과 검증 기준은 [대시보드 명세 4.4](../../specs/dashboard/spec.md#44-get-apiadminstudies)를 따른다.
