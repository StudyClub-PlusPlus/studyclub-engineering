# 대시보드 화면 표시는 PRD 를 따른다 — 「임박」·「오늘 마감」을 쓰지 않고 「외 N개」를 둔다

## 미리 알아야 할 것

| 단어 | 뜻 |
|---|---|
| **PRD** | 기획이 쓴 화면 문서. 화면이 무엇을 보여 주는지의 정본이다 ([console-dashboard](../../01-planning/stories/console-dashboard/PRD.md)) |
| **스펙** | 개발이 쓴 API 문서. 집계 기준과 API 모양의 정본이다 ([specs/dashboard](../../specs/dashboard/spec.md)). 3절 머리에 "표시 문구가 PRD 와 어긋나면 PRD 를 따른다"고 적혀 있다 |
| **현황 보드** | 대시보드 가운데의 「진행중 스터디」 · 「모집중 스터디」 칸 |
| **임박** | 마감이 가까운 모집을 따로 색칠해 알리는 표시 |

## 한 줄 요약

스펙을 쓴 뒤(10-07) PRD 가 바뀌었다(10-10 ~ 10-11). 화면 표시가 서로 다른 곳은 스펙의 규칙대로 **PRD 를 따랐다.**
서버 응답(API)은 바꾸지 않았다.

## 비유

설계도와 인테리어 시안이 다를 때를 생각해 보자. 벽이 어디 서는지는 설계도를 따르고, 벽지 색은 시안을 따른다.
여기서 설계도는 스펙(무엇을 어떻게 세나)이고, 시안은 PRD(화면에 어떻게 적나)다.

## 정해진 것 — 이렇게 만들었다

| 자리 | 스펙에 적힌 것 | PRD — 따른 것 |
|---|---|---|
| 3-2 모집중 마감 칸 | 72시간 남으면 「임박」, 마감 당일은 「오늘 마감」 | 둘 다 쓰지 않는다. `~MM-DD (D-N)` 으로 적고 당일은 D-0. 이미 닫힌 것(마감 경과 · 정원 마감)만 빨간색 |
| 2-1 활성 크루 카드 | 누르면 어디로 갈지 미정 | 누를 수 없다. 유저 목록은 가입자 전체라 이 수와 모수가 다르다 |
| 3-4 외 N개 | 두지 않는다 | 4건을 넘으면 「외 N개 스터디」. 누르면 「전체 보기」와 같은 곳으로 간다 |
| 5 추세가 비었을 때 | 「집계할 출석 대상이 없습니다.」 | 「아직 출석 기록이 없습니다.」 |
| 4 제목 | 크루 시간대 분포 | 크루 지역 분포. 범례는 한국 KST · 북미 동부 ET · 북미 서부 PT · 미분류 |

**PRD 에 있지만 이번에 만들지 않은 것** — 3-3 예정 행사. 행사 API 가 아직 없다 (스펙 1절, PRD 「개발 범위」 표).

서버는 지금도 임박 코드(`CLOSING_SOON`)를 준다. 화면은 이 코드를 보통 행과 같게 그린다. 그래서 백엔드는 고칠 것이 없다.

## 영향 — 누가 무엇을 해야 하나

- **대시보드 스펙 담당**: 스펙의 해당 절을 PRD 에 맞게 고친다. 7절의 「임박 표시」 · 「활성 크루 카드의 목록 이동」 행을 닫는다
- **백엔드**: 고칠 것 없다. 임박 코드를 응답에서 뺄지는 스펙을 고칠 때 함께 정한다
