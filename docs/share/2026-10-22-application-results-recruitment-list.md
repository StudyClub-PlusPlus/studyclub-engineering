# 신청 결과의 모집 회차 선택에 회차 목록이 필요하다

이슈 107 PRD는 모집 회차가 둘 이상이면 회차를 고르도록 요구한다.
현재 `GET /api/admin/studies/{studyId}/applications`는 `respondentCount`, `questions`, `applications`만 반환한다. `recruitmentId`를 생략하면 서버가 열린 회차, 없으면 가장 최근 회차를 선택한다.

신청 행에는 `recruitmentId`가 있지만 선택된 한 회차의 신청만 오며, 신청이 없는 회차는 알 수 없다. 현재 컨트롤러에는 스터디의 모집 회차 목록 조회 API도 없다.

FE는 기본 회차 조회와 URL의 `recruitmentId` 지정 조회, 질문별·응답자별 보기를 구현했다. 전체 회차를 임의로 추정하지 않아 회차 선택 드롭다운은 남아 있다.

목록 API 또는 신청 결과 응답에 회차 목록과 선택된 회차를 제공하는 계약이 필요하다. 회차 식별자와 화면 표시용 정보, 서버가 고른 기본 회차를 어떤 응답으로 제공할지 확인해 주세요. 이 문서는 API 경로나 응답 필드를 확정하지 않는다.
