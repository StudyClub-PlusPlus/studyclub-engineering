# 스터디 상세가 디스코드·자료실 링크를 누구에게나 줬다 — 참여자에게만 주도록 바꿨다

## 미리 알아야 할 것

| 단어 | 뜻 |
|---|---|
| API | 화면이 서버에 정보를 달라고 부르는 창구. 창구마다 주소가 있다 |
| 스터디 상세 API | `GET /api/studies/{id}`. 스터디 소개 페이지가 부르는 창구. 로그인 안 해도 부를 수 있다 |
| 내 스터디 API | `GET /api/me/studies`. 「내 스터디」 화면이 부르는 창구. 로그인한 본인 것만 준다 |
| 참여 중단 | 스터디 중간에 나간 사람. 명부 상태 `WITHDRAWN`. 크루 화면에는 「참여 종료」로 보인다 |
| 자료실 | 스터디마다 있는 구글 드라이브 폴더 링크 (`driveUrl`) |

비유하면 이래요. 「내 스터디」 화면에서는 나간 사람의 출입증을 회수하기로 했어요. 그런데 건물 로비 안내판(스터디 상세)에 출입 비밀번호가 그대로 적혀 있는 상황이에요.

## 한 줄 요약

스터디 상세 API 는 이제 디스코드 채널·자료실 링크를 **캡틴, 그리고 참여 중단이 아닌 참여자(네비게이터 포함)**에게만 준다. 그 밖의 사람(비로그인 포함)에게는 두 값이 `null` 이다.

## 왜 — 무엇이 문제였나

- 「내 스터디」 PRD (`01-planning/stories/crew-joined-studies/PRD.md` §4-6-2 · §4-6-3 · §3 권한): "참여 중단 행에는 채널·자료 URL 을 넣지 않는다. 직접 호출해도 서버가 거절한다"
- 그런데 스터디 상세 API 는 공개된 스터디면 누구에게나 `discordChannelUrl`·`driveUrl` 을 줬다. 09-27 백오피스 정보 탭 작업 때 응답에 같이 들어갔다
- 그래서 「내 스터디」 에서만 링크를 빼면, 나간 사람도 상세 페이지에서 링크를 다시 볼 수 있었다. 참여한 적 없는 사람도 마찬가지였다
- 사이트의 스터디 상세 화면은 이 두 링크를 쓰지 않는다(프론트 코드 확인). 그래서 막아도 깨지는 화면이 없다

## 정해진 것

| 누가 부르나 | `discordChannelUrl` · `driveUrl` |
|---|---|
| 캡틴 (`SYSTEM_ROLE = ADMIN`) | 채움 |
| 그 스터디의 네비게이터 (`LEADER`) | 참여 중단이 아니면 채움 — 사이트에서 이 값을 고친다. 하차한 네비게이터는 `null` |
| 참여자 — 참여 중·쉼·완주 (`ACTIVE`·`PAUSED`·`COMPLETED`) | 채움 |
| 참여 중단 (`WITHDRAWN`) | `null` |
| 그 밖의 회원 · 비로그인 | `null` |

백오피스 상세(`/api/admin/studies/{id}`)는 캡틴 전용이라 지금처럼 두 링크를 준다.

## 영향 — 누가 무엇을 해야 하나

- **프론트**: 스터디 상세에서 디스코드·자료실 링크를 보여 주고 싶다면, 두 값이 `null` 일 수 있다는 것만 기억하면 된다. 디스코드는 null 이면 사이트 기본 초대 링크로 안내한다
- **기획**: 참여 전 사람에게도 보여야 하는 링크(예: 클럽 로비 초대)가 있다면 알려 달라. 그건 이 두 값이 아니라 공개용 초대 링크로 따로 둔다
