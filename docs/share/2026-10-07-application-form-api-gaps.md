# 신청 폼 편집 권한·잠금 정보 보완

## 미리 알아야 할 것

신청 폼은 캡틴이 지원자에게 물어볼 질문을 만드는 화면이다.
API는 화면과 서버가 정보를 주고받는 창구다.
현재는 잠긴 문인지 표시가 없어서, 저장을 눌러야 잠겼다는 사실을 알 수 있는 상태다.

## 106번 범위

화면과 상호작용은 플레이그라운드를 우선한다.
프론트엔드를 먼저 구현하고 백엔드는 이번 작업에서 수정하지 않는다.
조회·저장은 `/api/admin/studies/{studyId}/application-form`을 사용한다.

## 현재 제한

- 조회 응답에 편집 가능 여부·잠금 사유가 없다. 상세 응답에도 담당 캡틴 ID와 모집 시작 이력이 없다.
- 조회 응답은 저장된 제목·설명이 비어 있어도 스터디 제목·한 줄 소개로 대체해 반환한다. 그래서 프론트는
  명시적으로 같은 문구를 저장한 경우와 기본값을 쓰는 경우를 구분할 수 없다. 현재는 조회값이 스터디 기본값과
  같으면 빈 값으로 복원해, 저장만 눌렀을 때 기본값이 고정되는 문제를 피한다.
- 따라서 첫 진입에 담당자가 아닌 캡틴의 편집 버튼을 숨기거나 잠금 상태를 정확히 표시할 수 없다.
- 저장 API는 현재 모든 캡틴에게 열려 있다. 담당 캡틴만 저장한다는 PRD와 차이가 있다. 스펙에도 임시 동작이 명시되어 있다.
- 서버는 신청이 한 건이라도 있거나 모집 시작 시각이 지난 회차가 있으면 저장을 409로 거절한다.
- 프론트는 409를 받으면 서버의 잠금 사유를 표시하고 편집·추가·삭제·저장을 막는다. 403도 읽기 전용으로 전환한다.
- 탭을 이동해도 해당 화면을 유지하므로 확인된 잠금은 유지된다. 새로고침 후에는 서버의 조회 정보가 없어 다시 판정할 수 없다.

## 후속 작업

백엔드 담당자는 조회 시 편집 가능 여부와 잠금 사유를 제공하는 계약을 검토한다.
저장 원본이 빈 값인지 알 수 있는 필드도 함께 제공해야 한다.
담당 캡틴만 저장하도록 할 경우 서버에서도 담당 여부를 검증해야 한다.
응답 계약이 정해지면 프론트는 최초 조회부터 읽기 전용 상태를 적용한다.
새 권한 정책이나 응답 필드 이름은 이 문서에서 확정하지 않는다.
