# 알림 실패 건 재발송 — 그 줄을 되돌려 다시 보낸다 · 기획과 다른 곳 둘

## 미리 알아야 할 것

- **발송 이력**: 회원에게 나간(또는 나가려던) 메일을 한 줄씩 적어 둔 목록이다. 운영 콘솔의 발송 이력 화면에서 본다.
- **실패 건**: 메일을 보내려 했지만 보내지 못한 줄이다. 상태가 「실패」다.
- **재발송**: 실패한 메일을 같은 주소로 한 번 더 보내는 일이다.
- **API**: 화면이 서버에 일을 시키는 창구다. 재발송 창구를 새로 만든다.
- **마스킹**: 이메일 가운데를 가리는 것이다. `j***@gmail.com`

비유하면 **택배 송장 대장**이다. 배송이 실패한 송장 한 장을 다시 접수 상태로 되돌려 재배송한다. 시도마다 송장을 새로 쓰지 않는다. 대장에는 알림 하나에 줄 하나만 있다.

## 한 줄 요약

**캡틴이 실패한 알림을 골라 다시 보낸다. 고른 줄이 그대로 「대기」로 돌아가 다시 나간다. 새 줄을 만들지 않으므로 DB 구조는 바뀌지 않는다.**

## 정해진 것 (개발 쪽)

1. **그 줄을 되돌린다.** 실패 → 대기. 시도 이력은 남기지 않는다. 기획(POL-0009 「알림 하나에 줄 하나」)과 같다.
2. **접수까지만 응답한다.** 보냈다는 뜻이 아니다. 끝(완료·실패)은 화면이 따로 확인한다.
3. **한 번에 최대 100건.** 거른 실패 건이 더 많으면 화면이 100건씩 나눠 보낸다.
4. **보낼 수 있는지는 서버가 판정한다.** 목록의 각 줄이 `canResend` 값을 받는다. 아래는 못 보낸다.
   - 실패가 아닌 줄 (대기·처리 중·완료, 탈퇴로 취소된 줄)
   - 탈퇴한 회원의 줄 (주소가 이미 지워져 보낼 곳이 없다)
5. **못 보내는 줄만 빼고 나머지는 보낸다.** 서버가 「접수한 줄」과 「건너뛴 줄과 이유」를 나눠 돌려준다. 한 줄 때문에 100건이 모두 막히지 않는다.
6. **전체 재발송은 화면이 모은 id 로 요청한다.** 서버가 조건으로 대상을 고르지 않는다(기획의 API 표 그대로). 화면은 목록 조회를 한 번에 100건씩 받아 id 를 모은다.
7. **이번 이슈에서 알림 템플릿은 건드리지 않는다.** 기존 「알림 템플릿」 메뉴는 그대로 두고 발송 이력은 새 메뉴 「알림 발송 이력」으로 둔다.

## 기획과 다른 곳 — 확인이 필요하다

### 1. 수신 주소를 서버가 가려서 보낸다 (질문)

- **기획**(발송 이력 PRD, POL-0009, POL-0007): 서버가 전체 이메일을 내려주고, 화면이 가린다. 줄의 눈 아이콘으로 펼친다.
- **개발**: 서버가 가린 채로 보낸다. 화면에 펼침이 없다.
- **이유**: 개발 규약이 응답에 개인정보 평문을 싣지 않도록 정한다. 유저 목록도 원본은 「보기」 API 로 따로 열고 감사 로그를 남긴다. 알림 목록은 한 번에 20건씩 전체 이메일이 응답에 실려 브라우저 개발자 도구에 그대로 보인다.
- **물어볼 것**: 눈 아이콘(줄별 펼침)을 이번에 빼도 되는가? 꼭 필요하면 유저 목록처럼 「보기」 API 와 감사 로그를 따로 만들어야 한다.

### 2. 발송 이력 PRD 의 모순된 문장 하나 (수정 요청)

- 발송 이력 PRD 이력 표 정책에 「재발송은 실패 건을 고치지 않는다. 그 기록은 그대로 두고 **새 건**을 만든다」가 있다.
- 같은 문서의 「서버가 접수한 뒤에 **그 줄이** 대기로 바뀐다」, 비고의 「알림 하나에 줄 하나」, POL-0009 와 부딪힌다.
- 개발은 「그 줄을 되돌린다」로 만든다. 이 문장을 같은 방향으로 고쳐 주세요.

## 영향 — 누가 무엇을 해야 하나

| 누가 | 할 일 |
|---|---|
| 기획 | 위 두 가지를 답한다. 재발송 문구(확인 창, 결과 토스트)는 PRD 에 이미 있어 별도 확정은 필요 없다 |
| 백엔드 | 스펙 `specs/notification/spec.md` 리뷰. 통과하면 `POST /api/admin/notifications/resend`, 목록 응답의 `canResend`, `?ids=` 조회, 정렬 보조 키(`ID DESC`), `limit` 상한을 구현한다. 마이그레이션은 없다 |
| 프론트 | 스펙이 합쳐지면 `back-office-front` 에 「알림 발송 이력」 메뉴와 화면을 만든다. 필터·페이지는 URL 쿼리에 둔다 |

## 같이 정리한 것

기존 알림 스펙이 코드와 어긋나 있어 **별도 커밋으로** 먼저 고쳤다. 경로는 `/back-office/*` 가 아니라 `/api/admin/*` 이고, 인가는 「로그인만 되면 호출 가능」이 아니라 캡틴만(`@RequireAdmin`)이다.
