# 디스코드 봇은 「누가 시켰나」를 더 이상 따지지 않는다 — 권한 판단은 백엔드가 한다

## 미리 알아야 할 것

- **디스코드 봇**: 우리 디스코드 서버에서 채널·역할(role)을 만들고 메시지를 올리는 프로그램이다.
  백엔드(웹 서버)가 봇의 **API**(프로그램끼리 정보를 주고받는 창구)를 불러서 일을 시킨다.
- **captain · navigator 역할**: 디스코드 서버 안에서 캡틴 · 네비게이터에게 붙는 역할이다. 서버 전체에 하나씩 있다.
- **`X-API-Key`**: 백엔드가 봇을 부를 때 함께 보내는 비밀 열쇠다. 이게 맞으면 봇은 "백엔드가 보낸 요청" 이라고 믿는다.
- **`X-Discord-User-ID`**: 요청마다 함께 보내는 "이 일을 시킨 사람" 의 디스코드 번호다.
- **시스템 호출**: 사람이 아니라 백엔드가 스스로 봇을 부르는 경우. 이때는 위 번호 칸에 봇 자신의 번호(`DISCORD_BOT_ID`)를 넣는다.

## 한 줄 요약

봇은 요청을 받으면 **열쇠(`X-API-Key`)만 확인하고 시킨 대로 한다.** "이 사람이 캡틴인가" 같은 검사는 백엔드만 한다.

## 왜 — 지금 뭐가 문제였나

지금까지는 같은 검사를 **두 군데서** 했다. 백엔드가 "이 사람은 이 스터디의 캡틴이다" 를 확인하고,
봇이 한 번 더 "이 사람에게 디스코드 captain 역할이 있나" 를 확인했다. 없으면 봇이 **403**(권한 없음)으로 거절했다.

비유하면 이렇다. 회사 경비실(백엔드)이 사원증을 확인하고 들여보냈는데, 엘리베이터(봇)가 또 사원증을 보자고 한다.
엘리베이터는 사원증 명단이 경비실보다 낡았다. 그래서 경비실이 통과시킨 사람을 엘리베이터가 막는 일이 생긴다.

실제로 생긴 문제:

- **백엔드가 스스로 부르는 일이 막혔다.** 네비게이터 역할을 떼고 붙이는 창구는 captain 만 받아서,
  백엔드가 시스템 호출로 부를 수 없었다 ([10-18 디스코드 자동화 질문 5 · DSC-06](2026-10-18-discord-automation-gap.md)).
- **판단 기준이 둘로 갈렸다.** 백엔드에서는 ADMIN 인데 디스코드에서 captain 역할이 없으면 스터디 생성이 실패했다.
- 봇은 "그 스터디의" 캡틴인지는 어차피 볼 수 없었다. 진짜 판단은 원래부터 백엔드 몫이었다.

## 정해진 것

1. **봇은 요청자를 검사하지 않는다.** 길드 멤버인지도, captain · navigator 역할이 있는지도 보지 않는다.
   그래서 봇 API 에서 **403 은 더 이상 나오지 않는다.** "요청자가 길드에 없음" 404 도 없어졌다.
2. **`X-Discord-User-ID` 는 그대로 필수다.** 백엔드 코드는 바꿀 것이 없다.
   이 번호는 이제 메시지의 `발신: <@번호>` 줄(alert · 스터디 채널 메시지)에만 쓰인다.
3. **시스템 호출을 따로 구분하지 않는다.** 봇 쪽 `DISCORD_BOT_ID` 설정은 지웠다.
   백엔드는 계속 이 값을 읽어서 번호 칸에 넣는다 — alert 에 「봇이 보냄」 으로 보이게 하려는 것이다.
4. **그대로 남는 봇 쪽 규칙**: 일반 역할 창구로 captain · navigator · `@everyone` 역할을 붙이거나 떼는 것은
   여전히 400 으로 막는다. 이건 "누가" 가 아니라 "어떤 역할을" 의 규칙이다.

## 영향 — 누가 무엇을 해야 하나

- **백엔드**: 봇을 부르기 **전에** 그 사람이 이 일을 해도 되는지 반드시 확인한다. 이제 그게 유일한 관문이다.
  지금 봇을 부르는 곳은 둘이다 — 스터디 생성(ADMIN API 뒤라 이미 확인됨)과 스터디 역할 동기화(시스템 호출).
  새로 봇을 부르는 코드를 짜면 권한 확인을 **같은 PR 에** 넣는다.
- **DSC-06 은 할 일이 없어졌다.** 네비게이터 역할 창구도 시스템 호출을 받는다. DSC-08 · DSC-09 의 네비게이터 role 부분은
  DSC-06 을 기다리지 않아도 된다. 질문 4(디스코드 미연동 캡틴)도 시스템 호출로 부르면 사라진다.
- **운영**: 봇 컨테이너의 `DISCORD_BOT_ID` 는 이제 읽지 않는다. 지워도 되고 남겨도 된다.
  백엔드의 `DISCORD_BOT_ID`(`discord.bot-id`)는 **계속 필요하다.**
- **기획 · 디자인**: 화면에 바뀌는 것은 없다.
