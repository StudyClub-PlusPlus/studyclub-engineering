### 반영한 문안

1. Google·Apple 로그인, 닉네임·시간대, 선택 프로필 사진, 마케팅 수신 설정, 디스코드 연동 해제 조건과 마이페이지 탈퇴를 실제 기능에 맞췄다.
2. 사이트 문의의 목적·수집 항목·열람 범위를 분리했다. 접수·오류 확인·처리 항목을 표로 안내하고 첨부 사진을 선택 항목으로 표시한다. 내부 파일 식별자는 첨부 사진에 딸린 관리 정보로 보며 별도의 공개 문구를 반복하지 않는다.
3. 사이트 문의 내용·답변·첨부 사진은 작성자와 문의 처리 권한이 있는 캡틴이 열람하도록 제한한다. 운영 메모는 운영진 업무용이다. 사진 응답은 로그인·권한·만료·삭제 상태를 확인하고 임시 저장을 제한한다.
4. 답변한 문의는 **첫 답변일부터 1년**, 미답변 문의는 **접수일부터 1년**으로 유지한다. 탈퇴나 답변 수정으로 기간을 다시 시작하지 않는다. 첨부 사진은 **문의 만료와 탈퇴 중 먼저 도래하는 때**에 삭제한다.
5. 등록되지 않은 파일은 업로드 후 24시간이 지나면 정기 삭제 대상에 포함된다. 정확히 24시간에 파일이 모두 삭제된다고 약속하지 않는다.
6. 운영자의 이메일·디스코드 조회 1년, 캡틴·네비게이터 권한 변경·말소 3년, 일반 크루 참여 중단·분석 중단 요청 처리 기록 1년 및 IP를 기존 합의대로 반영했다.
7. 같은 스터디·반 출석부와 운영진의 열람 범위, 디스코드 알림의 전송 항목과 수동 정리 사실을 설명한다. 디스코드 메시지에 새로운 삭제 주기를 임의로 정하지 않는다.
8. AWS S3·SES 서울 리전을 반영한다. CloudFront의 공개 이미지 전달은 프로필 사진·스터디 대표 이미지 등으로 한정하고, 문의 첨부 사진의 권한 확인 후 전달과 구분한다.
9. 실제 코드의 일일 정리·파일 삭제 실패 재시도에 맞춰 공개 문구는 ‘정기적으로 자동 삭제’로 설명한다. 실행 간격과 실패 재시도는 구현·검토 기록에서 관리한다. 문의 사진 만료·삭제 중에는 사이트에서 열 수 없다. 공개 이미지의 캐시와 문의 사진을 혼동하지 않는다.
10. 확인되지 않은 모든 데이터의 ‘정기 백업’ 약속은 제거했다. 문의 자유입력에 개인정보가 들어갈 수 있어 민감정보를 절대 수집하지 않는다는 표현 대신 입력을 요구하지 않는다는 사실과 불필요한 정보의 입력 주의를 안내한다.

### 유지하는 결정과 범위

- 동의 버전은 **1.0**을 유지한다. GA4·Amplitude·Clarity의 전송·보관·삭제·거부 안내는 의미를 바꾸지 않는다.
- 신청 화면 안내·업로드 동의 UI·신청서 자유입력 삭제·추가 기능 개발은 이번 문안 수정에 포함하지 않는다.
- 스테이징 반영과 검증 후 `beta` 대상 PR로 검토한다. 운영 환경 배포와 최종 공개 일정은 별도로 정한다.
- 이용약관의 `updatedAt` **2026-09-10**, 개인정보처리방침의 `updatedAt` **2026-11-08**과 기존 시행일을 유지한다. 이 날짜가 이번 수정 내용의 소급 시행을 의미하지 않는다. 실제 공개 일정이 정해지면 표시 날짜와 변경 안내를 함께 정한다.

### 같은 날 문안 간소화

- 사용자 요청에 따라 아래 네이버·카카오·당근의 운영 중인 정책을 다시 확인했다. 수집 항목·목적·기간·위탁 사항은 표로 정리하고, 구현 설명과 중복 문단을 줄이는 작성 방식을 참고했다. 다른 회사의 수집 근거나 보유기간을 그대로 적용하지 않았다.
- 약관은 가입·탈퇴와 이용 관계를 설명하고, 탈퇴 후 보관하는 정보의 세부 기준은 개인정보처리방침 제4조로 모았다.
- 문의 수집 항목은 접수·오류 확인·처리의 3행 표로 정리했다. 운영 기록의 목적, 원문을 로그에 복제하지 않는다는 설명, 계정을 복원하지 않는다는 설명 등은 삭제하거나 해당 조항의 안내로 통합했다.
- 디스코드 알림은 가입·신청·탈퇴별 전송 항목을 짧은 목록으로 바꿨다. 수동 정리와 메시지가 탈퇴만으로 자동 삭제되지 않는다는 사실은 유지했다.
- 사진의 보유기간은 제4조, 열람자는 제6조, 만료·삭제 중 열람 제한과 공개 이미지 캐시는 제9조에서 안내한다. 서버 인증·삭제 재시도 등의 상세 구현은 중복 기재하지 않는다.
- 보유기간 표, 분석 도구의 수집·이전·삭제·거부 안내, 사진 열람 권한, 미확정 정보는 종전 결정대로 유지한다. 이번 간소화는 미확정 사항의 확정이나 실제 처리 방식의 변경이 아니다.

### 이미 확인된 인프라 사실

주영님의 디스코드 답변을 사용자가 이 대화에 전달한 내용과 현재 코드의 근거를 구분한다. 이번 문안 작업에서 AWS 계정을 직접 조회한 결과가 아니다.

| 항목 | 확인된 사실 | 문안에 반영한 범위 |
|---|---|---|
| S3·SES | 둘 다 서울 리전 `ap-northeast-2`라는 담당자 답변 | 사진 원본 저장·이메일 발송에 서울 리전 사용 |
| S3 사본 | 버전 관리·수명주기 규칙·리전 간 복제·AWS Backup 미사용이라는 담당자 답변 | 모든 파일에 별도 백업이 있다는 표현을 사용하지 않음 |
| 공개 이미지 | CloudFront `PriceClass_All`, 국가 제한 없음, 업로드 시 `max-age=86400`, 삭제 시 무효화 없음이라는 담당자 답변 | 프로필 사진 등 공개 이미지에는 해외 임시 사본이 생길 수 있고 원본 삭제 후에도 캐시에 따라 표시될 수 있음 |
| 새 문의 사진 | #537의 `private/feedbacks` 저장 및 권한을 확인하는 서버 전달, `private, no-store` 응답 | 문의 사진에 공개 이미지 전달 경로를 사용하지 않는다고 설명 |

캐시 24시간은 캐시 재사용·재확인 기준이다. **24시간이 지나면 전 세계 모든 사본이 물리적으로 완전히 삭제된다**고 보장하지 않는다. 실제 캐시 정책과 오류 시 동작도 영향을 줄 수 있다. [AWS 캐시 문서](https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/Expiration.html)

### #537 적용 확인과 기존 사진

- 새 파일은 비공개 경로에 저장하지만, 기존 `gigs/feedbacks` 파일을 옮기거나 기존 CloudFront 주소를 무효화하지 않는다. 스펙에는 기존 파일을 테스트 기록으로 취급한 결정이 남아 있다.
- 사용자에게 비공개를 안내하는 문안을 실제 환경에 공개할 때에는 새 파일을 S3·CloudFront 주소로 직접 열 수 없는지와 API 권한 제한을 확인한다. 저장 경로 이름이나 머지 여부만으로 검증을 대신하지 않는다.
- 예전 공개 파일에 실제 개인정보가 들어 있는지 확인되면 해당 파일 삭제 또는 비공개 이전과 기존 공개 경로 정리가 필요하다. 이번 문안 변경은 과거 파일을 삭제하거나 이전하지 않는다.
- 파일 만료·삭제 중 열람 차단은 [FeedbackImageService.java](../../backend/api/src/main/java/com/studyclub/api/feedback/FeedbackImageService.java), 탈퇴 시 사진 정리는 [AccountDeletionService.java](../../backend/api/src/main/java/com/studyclub/api/auth/AccountDeletionService.java)에 근거한다.
- 보관 기준과 하루 간격 자동 정리는 [데이터 보관 스펙](../../specs/data-retention/spec.md), 첨부 사진 구조와 기존 파일 예외는 [문의 스펙](../../specs/feedback/spec.md)을 따른다.

### 수정 검증

- core-front 및 의존 패키지의 lint·TypeScript 검사 7개 작업, 변경 문안의 Prettier 검사와 디자인 이탈 검사 통과.

- 간소화 전후의 보유기간 표·국외 이전 표 전체, 분석 도구의 수집·위탁 항목 및 제13조 문구가 동일함을 확인했다.
- 로컬 실제 화면에서 문의 수집 항목 표와 파기 안내를 확인했다. PC(1,100px)와 모바일(390px)의 표 표시를 확인했으며, 모바일 렌더링 완료 후 페이지 가로 넘침이 없었다.
- 이 검증은 문안과 프런트엔드 확인이다. 실제 AWS 접근 차단·배포 상태·보관기간 경과 후 삭제를 다시 검증한 결과는 아니다.

### AWS 담당자에게 물어볼 질문

비밀번호·키·버킷 이름·내부 주소는 필요 없다. 서비스명, 국가/리전, 기간과 설정의 요약만 확인한다. 스테이징과 실제 사용자용 환경이 다르면 각각 답을 받는다.

1. **S3:** 프로필 사진과 문의 사진을 저장하는 실제 리전/국가는 어디인가요? 다른 리전으로 복제하거나 별도로 백업하나요?
2. **S3 삭제:** 버전 관리나 삭제 방지(Object Lock)가 켜져 있나요? 파일 삭제 후 이전 버전·복제본·백업이 남는다면 각각 언제 완전히 없어지나요?
3. **CloudFront:** 프로필·문의 사진 모두 CloudFront로 전달하나요? 실제 캐시·처리 가능한 국가와 제한 설정은 무엇인가요? 삭제한 사진의 캐시 보관 시간과 삭제 시 무효화 여부는 어떻게 되나요? 가격 등급이나 접속 국가 제한만으로 모든 데이터가 국내에만 저장된다고 단정하지 않습니다.
4. **SES:** 이메일을 발송하는 실제 리전/국가는 어디인가요? 수신자 주소·메일 본문·발송/반송 기록을 별도로 저장하는 서비스가 있다면 그 서비스의 국가와 보관 기간은 무엇인가요?
5. **계약·연락처:** 개인정보 처리 계약상 AWS 수탁 법인명과 이용자가 문의할 수 있는 개인정보 관련 연락처는 무엇인가요? 저장·복제·지원 과정에서 해외 처리가 있다면 국가와 위탁 관계를 확인할 수 있는 자료가 있나요?

답을 받은 뒤 제7조의 수탁자 표시와 제8조의 국외 이전 항목을 함께 확정한다. "AWS는 미국 회사니까 미국", "S3가 서울이니까 국외 이전 없음" 중 어느 쪽도 설정 확인 없이 채택하지 않는다.

## [1] 개인정보 보호책임자 — 방침 제14조

```
성명:   강주영
직책:   개인정보 보호책임자
```

- `privacy@` 는 **이미 수신되는 주소**다. 운영 도메인에 걸린 기존 별칭이라 새로 만들 것이 없다.

- 여기 이름이 올라가는 사람이 법적 책임자다. 클럽이 법인이 아니고 운영 주체가 1인이므로 합의 대상이 없다 — 서비스 운영 주체인 강주영으로 간다. 팀원 수와 무관하며, 보호책임자는 조직 규모가 아니라 **처리 주체**를 따른다.

여기에 **Cloudflare R2 도입이 예정**되어 있어(아래 참조) "있음" 은 사실상 되돌릴 수 없다. R2 는 리전을 고정하는 개념이 약하고 처리자가 미국 법인이다. 지금 "없음" 으로 적어두면 R2 붙는 날 방침이 곧바로 허위가 된다.

### 참고 — "없음" 이 가능했던 조건

기록용으로만 남긴다. R2 예정이 있는 한 성립하지 않는다.

1. 접수용 메일을 국내 메일 서비스로 이전
2. 디스코드 연동을 방침 제2조 수집항목에서 제외
3. 오브젝트 스토리지를 국내 리전(AWS S3 서울 등)으로 단일화

## [5] 국외 이전 상세 — 방침 제8조 표 (위 [4] = 있음 기준)

현재 표에 남아 있는 행은 「이용 목적: 서버 운영 및 데이터 보관」 인데, 클럽은 **서버를 위탁하지 않으므로** 그대로 쓰면 사실과 다르다. 아래 2행으로 교체한다.

| 이전받는 자 (연락처) | 이전 국가 | 이전 일시·방법 | 이전 항목 | 이용 목적 | 보유·이용 기간 |
|---|---|---|---|---|---|
| Google LLC (`dpo-google@google.com` ⚠️) | 미국 | 문의·권리행사 접수 시 정보통신망을 통한 전송 | 이메일 주소, 이름, 문의 내용 | 고객 문의 접수·응대 | 문의 처리 완료 후 1년 |
| Discord Inc. (`privacy@discord.com` ⚠️) | 미국 | 디스코드 연동 시 정보통신망을 통한 전송 | 디스코드 계정 식별자·사용자명 | 커뮤니티 채널 연동 | 연동 해제 시까지 |

이전의 법적 근거는 기존 표와 동일하게 **「개인정보 보호법」 제28조의8 제1항 제3호 가목**(계약의 이행을 위한 처리위탁·보관)을 쓴다.

> ⚠️ **두 연락처는 미검증이다.** 공개된 주소로 알려진 값일 뿐이므로, 싣기 전에 각 사의 개인정보처리방침에서 현재 값을 직접 확인할 것. 법정 기재사항이라 틀리면 그 자체가 흠이 된다.

## [6] 수탁자 — 서버·인프라 — 방침 제7조 표

```
현재: 해당 없음 (클럽이 직접 운영하는 자체 서버)
```

- 서버가 자체 하드웨어라 **위탁 자체가 발생하지 않는다.**
- 제7조 표의 「실제 서버·인프라 제공자 / 서비스 서버 운영 및 데이터 보관」 행을 **삭제**한다.
- 클라우드 사업자를 적으면 사실과 다르다. 현재 그 안내문이 본문에 그대로 노출 중이므로 우선순위가 높다.
- 오브젝트 스토리지(S3·R2) 도입 시 이 자리에 **저장 위탁**으로 행이 생긴다 → 아래 참조.

## [7] 수탁자 — 이메일 발송·문의 응대 도구 — 방침 제7조 표

```
현재: 미사용 → 해당 행 삭제
```

- 백엔드 전체에 **메일 발송 코드가 없다.** JavaMail·SMTP·메일 SDK·외부 메일 API 모두 0건.
- 인증이 구글 소셜 로그인 단독이라 비밀번호 재설정 메일조차 존재하지 않는다.
- 운영용 메일 발송 설정이 별도로 있으나 **제품에 연결돼 있지 않은 테스트 도구**다.

## 도입 예정 서비스와 그때 해야 할 개정

**원칙: 개인정보처리방침은 현재 처리하고 있는 사실만 적는다.** 예정을 미리 적으면 그것도 허위 기재다.
아래는 각 서비스가 **실제로 붙는 날** 무엇을 함께 고쳐야 하는지의 목록이다. 방침 기존 조항에 따라 시행 전 공지가 필요하고, 회원에게 불리한 변경이면 이메일 개별 통지가 필요하다.

| 용도 | 서비스 | 리전·국가 | 제7조 (수탁) | 제8조 (국외이전) | 함께 고칠 것 |
|---|---|---|---|---|---|
| 메일 발송 | AWS SES | 서울 (`ap-northeast-2`) | 행 추가 — "이메일 발송" | ❌ 국내 리전 | — |
| 오브젝트 스토리지 | AWS S3 | **서울 리전으로 고정할 것** | 행 추가 — "파일 저장·보관" | ❌ (서울 고정 시) | 제2조에 업로드 파일 항목 추가 |
| 오브젝트 스토리지 | Cloudflare R2 | 리전 고정 개념 약함 / 미국 법인 | 행 추가 — "파일 저장·보관" | ⭕ **행 추가 필수** | 제2조에 업로드 파일 항목 추가 |
| 알림톡 | NHN 클라우드 | 국내 | 행 추가 — "알림톡 발송" | ❌ 국내 | **제2조에 휴대전화번호 추가 + 별도 동의** |
| 이용 분석 | Amplitude | 미국 | ✅ 반영 (2026-10-14) — "서비스 이용 통계 분석" | ✅ 반영 — 행 추가 | 제1조 제5호 · 제2조 4 비고 · 제4조 보유기간 · 제13조 쿠키 |
| 이용 분석 | Google Analytics 4 · Microsoft Clarity | 미국 | ✅ 확정 (2026-10-25) — 시행 2026-10-25 | ✅ 반영 — 행 2개 추가 | 제2조 4 분석 도구 표 · 제4조 보유기간 · 제13조 쿠키 표 · Microsoft Advertising 고지 · 시행일 |

**사람이 정할 것**

- ★ **시행일·사전 공지** — 방침 제16조(처리방침의 변경)대로 시행 전 공지가 필요하다. production 배포 전에 시행일을 정한다

### GA4 · Clarity — 확정 (2026-10-25, 시행 2026-10-25)

그로스 계측 PR(GA4·Clarity, production 빌드만)과 같이 나가는 개정이다. 법무 자리는 아래 값으로 확정했다.

- 처리 근거: 정당한 이익(「개인정보 보호법」 제15조 제1항 제6호)
- 국외 이전 근거: 처리방침에 공개한 처리위탁·보관(제28조의8 제1항 제3호)
- 보유기간: GA4 14개월(속성 설정도 14개월), Amplitude 수집일부터 14개월 후 지체 없이 삭제, Clarity 30일(표본 최대 9개월)
- 회원 번호와 함께 기록되는 이용 분석 정보는 개인정보로 취급
- Microsoft Advertising 고지 문단 유지
- 국내 이용자 대상 쿠키 사전 동의 창은 두지 않고 거부 방법을 고지
- 시행일 2026-10-25 (2026-10-25 결정으로 공지 기간 없이 당김. 처음 안은 2026-11-01·7일 전 공지)

- Clarity 는 회원 번호를 `identify` 로 붙이고, 프로필 카드는 `data-clarity-mask` 로 가린다. 마스킹 모드(Strict/Balanced)는 Clarity 프로젝트 설정에서 확인
- Clarity 이용약관상 Microsoft Advertising 고지 문장을 제13조에 넣었다

### 항목별 주의

- **AWS SES** — 발신 도메인·자격증명이 이미 준비돼 있다. 서울 리전이므로 국외 이전 판정에 영향 없다. 붙는 즉시 제7조에 수탁자 1행이 생긴다.
- **AWS S3** — 버킷 리전을 **반드시 서울로 고정**한다. 다른 리전으로 만들면 제8조에 행이 하나 더 늘고, 이용자에게 거부권 안내까지 붙는다. 리전 선택 한 번으로 문서 분량이 갈린다.
- **Cloudflare R2** — 국외 이전 확정 요인이다. S3 와 R2 를 **둘 다** 쓸 이유가 분명하지 않다면 하나로 줄이는 쪽이 문서·법적 부담 모두 적다. 굳이 R2 를 쓸 이유(에그레스 비용 등)가 있다면, 회원 개인정보가 담긴 파일은 S3(서울)에, 공개 정적 자산만 R2 에 두는 분리를 검토한다 — 그러면 R2 는 개인정보 처리에서 빠진다.
- **프로필 사진 (AWS S3 + CloudFront)** — 2026-10-07 결정으로 받기로 했다 ([POL-0007](../../01-planning/_registry/policies/POL-0007-account-data.md), [profile-image 스펙](../../specs/profile-image/spec.md)). **기능을 켜는 날** 함께 고칠 것:
  - 제2조 2항 표 — 선택항목에 「프로필 사진 (마이페이지에서 등록 시)」 추가
  - 제7조 — 수탁자 AWS 「파일 저장·보관」 행 추가 (위 S3 행과 같다)
  - 제4조 — 보유기간: 회원 탈퇴 또는 사진 삭제 시 즉시 파기
  - ★ **판단 필요 — CloudFront 의 국외 이전 해당 여부.** 원본은 서울 리전 S3 에 있지만, CloudFront 는 보는 사람과 가까운 해외 엣지에 사본을 캐시한다. 공개 이미지라도 개인정보(얼굴 사진)라 제8조 해당 여부를 확인한다. 해당되면 제8조 행과 거부권 안내가 붙는다
  - 시행 전 공지 (제2조 수집항목 추가)
- **NHN 클라우드 알림톡** — 이게 가장 무겁다. 알림톡은 **휴대전화번호 수집**이 새로 필요하고, 현재 방침 제2조 수집항목에 전화번호가 없다. 수집항목 추가 + 마케팅성 발송이면 별도 동의(수신동의)까지 필요하다. 또 NHN 클라우드는 발송 대행이고 실제 전달은 카카오를 거치므로 **재위탁 관계**를 제7조 제2항 기준으로 확인해야 한다.
