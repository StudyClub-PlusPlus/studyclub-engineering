# 알림 규칙 추가하기

Grafana 에 알림을 하나 더 다는 절차다. 왜 이렇게 만들었는지와 이미 있는 규칙 목록은
[`specs/observability-stack/spec.md`](../../specs/observability-stack/spec.md) 의 「알림」 절에 있다.

> **알림은 Grafana 내장 `discord` contact point 가 아니라 `webhook` 으로 나간다.** 내장 타입은
> 채널 webhook URL 하나만 받아서 봇 토큰을 넣을 수 없다. 자세한 이유는 스펙의 「알림」 절.
>
> **화면을 짚어가는 안내는 Notion 「알림 시스템 — 구조와 사용법」** 에 캡처와 함께 있다.
> Grafana 주소 · Org · 데이터소스 uid 같은 환경값도 거기 있다 — 이 레포는 PUBLIC 이다.

## 1. 쿼리

Alerting → Alert rules → New alert rule. 이름은 `[studyclub] 응답 지연` 처럼 쓴다(앞머리
대괄호는 알림 메시지에서 자동으로 떼어낸다).

- **사람이 읽는 단위로 만든다.** 비율이면 `* 100`, 초면 `* 1000` 을 **쿼리에** 넣고 임계값도
  같이 올린다. 메시지에서만 환산하면 Grafana 화면과 값이 어긋난다
- **빈 결과가 아닌지 본다.** 라벨 이름이 하나 틀려도 오류 없이 **영원히 조용하다.**
  `Preview alert rule condition` 으로 값이 나오는지 먼저 확인한다
- **uri 별로 쪼갤지 정한다.** `sum by (uri)` 로 쪼개면 터진 엔드포인트마다 알림이 따로 생기고
  메시지에 그 uri 가 찍힌다

## 2. 폴더와 라벨

폴더 `studyclub`, 평가 그룹 `studyclub-api`. **라벨 두 개는 반드시 넣는다.**

| 라벨 | 값 | 하는 일 |
|---|---|---|
| `project` | `studyclub` | 알림 정책이 이 라벨로 채널을 찾는다 |
| `severity` | `critical` / `warning` | 메시지 색을 고르고, 멘션 여부를 가른다 |

`critical` 은 지금 봐야 하는 것, `warning` 은 지켜볼 것. 애매하면 `warning` 으로 시작한다 —
알림이 배경음이 되면 아무도 안 본다.

## 3. 주석 네 개

메시지 본문은 전부 주석에서 나온다. `metric` 과 `unit` 은 기본 칸에 없어서
`+ Add custom annotation` 으로 추가한다.

| 주석 | 무엇 | 예 |
|---|---|---|
| `summary` | 무슨 일이 났는가 | `5xx 비율이 5% 를 넘었다` |
| `description` | 뭘 볼 것인가 + 링크 | `응답 코드별 그래프를 본 뒤 같은 시각 로그를 본다.` |
| `metric` | 값의 이름, 집계 구간 포함 | `5xx 비율 (5분)` |
| `unit` | 단위 | `%` · `ms` · `건` · `대` |

**설명에 설계 근거를 쓰지 않는다.** 새벽에 알림을 받은 사람이 읽는 자리다. 근거는 스펙에 쓴다.
uri 는 제목이 이미 보여주므로 `summary` 에 넣지 않는다.

## 4. 저장하고 확인

규칙 목록에서 **`health` 가 `ok`** 인지 본다. `error` 면 쿼리가 틀렸고, 계속 `nodata` 면 라벨이
안 맞는다 — 둘 다 조용히 실패하므로 여기서 잡아야 한다.

모양까지 보려면 임계값을 잠깐 뒤집어 실제로 터뜨렸다가 되돌린다. 이때 두 가지를 지킨다.

- **라벨을 바꿔 재발화시키지 않는다.** Grafana 가 이전 조합을 별개 인스턴스로 보고 해소 처리해서
  없는 문제가 있는 것처럼 보인다. **일시정지 → 해제**로 한다
- **테스트는 개인 채널로 돌리되 토큰과 채널을 짝으로 바꾼다.** 한쪽만 바꾸면 `403` 이다.
  토큰 교체는 **`Reset` 을 먼저** 누른다
