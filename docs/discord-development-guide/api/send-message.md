# Send Message

**경로로 지정한 채널**에 메시지 하나를 올린다. 스터디 채널에 공지·안내를 남기는 용도이고, 요청에 넣은 유저들을
**멘션해 알림을 울릴 수 있다.** 채널이 고정인 [`send-alert-message`](send-alert-message.md) ·
[`send-announcement-message`](send-announcement-message.md) 와 달리 **채널을 호출자가 고른다.**

> ⚠️ **아직 구현 전이다.** 이 문서는 구현할 계약이다.
> 공통 요청 헤더는 [`common-header.md`](common-header.md) 를 따른다.
> **대상 길드는 하나로 고정**이라 요청에 길드를 넘기지 않는다.

## 요청

```
POST /api/v1/channels/{discordChannelId}/msg
```

| 경로 변수 | 타입 | 설명 |
|-----------|------|------|
| `discordChannelId` | string | 메시지를 올릴 **Discord 텍스트 채널 ID**(snowflake) |

헤더는 [공통 헤더](common-header.md) 전부 — `Idempotency-Key` 는 **필수**다 (로그 추적용 — [중복 전송과 재시도](#중복-전송과-재시도) 참고).

**captain 역할 또는 navigator 역할을 가진 멤버만 호출할 수 있다.** [`send-alert-message`](send-alert-message.md#요청) 와
같은 규칙이다 — 봇이 `X-Discord-User-ID` 로 길드 멤버를 조회해 둘 중 **하나라도** 갖고 있는지 확인하고,
둘 다 없으면 **403** 이다.

captain 역할과 navigator 역할은 둘 다 길드에 **이미 존재하는** 역할이다. 이 엔드포인트는 어느 것도 만들지 않고,
찾지 못하면 보내지 말고 실패한다. 둘 다 **설정값으로 ID 를 받는다**
(예: `DISCORD_CAPTAIN_ROLE_ID` · `DISCORD_NAVIGATOR_ROLE_ID`) — 이름으로 찾지 않는다.

```jsonc
{
  "discordStudyId": "1327394882193883136",
  "msg": "이번 주 모임은 목요일 저녁 9시로 옮깁니다.",
  "discordUserIds": ["327394882193883136", "412938471293847123"]
}
```

| 필드 | 타입 | 필수 | 제약 |
|------|------|------|------|
| `discordStudyId` | string | O | snowflake. **로깅 + 채널 소속 검증용** — [아래](#discordstudyid-의-역할) 참고 |
| `msg` | string | O | 1자 이상, 공백만으로 이루어지면 안 된다. 길이 상한은 [멘션 줄과 합쳐서](#올리는-메시지) 잰다 |
| `discordUserIds` | string[] | O | 멘션해 알림을 울릴 유저의 snowflake 배열. **빈 배열 허용** — 멘션 없이 올린다. 중복은 무시. **최대 40명** (중복을 뺀 뒤 센다) |

**모든 ID 는 문자열이다** — snowflake 는 64비트라 JSON 숫자로 보내면 JS 호출자에서 정밀도가
깨진다 ([common-header.md](common-header.md#x-discord-user-id) 와 같은 규칙). 검증은 `^[0-9]{17,20}$` 로 한다.

### `discordStudyId` 의 역할

[`create-study`](create-study.md#성공-응답) 가 돌려준 **스터디 카테고리의 채널 ID** 다. 두 가지에 쓴다.

1. **로깅** — 어떤 스터디 때문에 이 메시지가 나갔는지 로그에 남긴다 ([assign-role](assign-role.md#discordstudyid-의-역할) 과 같다).
2. **채널 소속 검증** — `discordChannelId` 채널이 **그 카테고리 바로 아래에 있는지** 확인한다
   (`channel.category_id == discordStudyId`). 아니면 보내지 않고 **404** 다.

2번이 이 엔드포인트를 **스터디 채널 안으로 가둔다.** navigator 역할은 [길드 전체에 하나](assign-navigator-role.md#navigator-는-스터디별-역할이-아니다)라,
검증이 없으면 navigator 가 스터디와 무관한 채널(운영 채널 등)에도 봇 이름으로 멘션을 뿌릴 수 있다.

검증하지 **않는** 것:

- **그 카테고리가 정말 스터디 카테고리인지.** 어떤 카테고리가 스터디인지의 주인은 백엔드다 —
  신뢰 경계는 `X-API-Key` 가 긋고, 백엔드가 보낸 `discordStudyId` 는 스터디 카테고리로 본다
  ([assign-role 의 신뢰 모델](assign-role.md#배정할-수-있는-역할의-범위) 과 같은 결).
- **요청자가 그 스터디의 captain · navigator 인지.** 두 역할 모두 길드 전체에 하나라 봇이 볼 수 있는 건
  "역할이 있다" 까지다. 스터디 단위 권한 검사가 필요하면 백엔드가 호출 전에 한다.
- **멘션 대상이 그 스터디 멤버인지.** 위와 같은 이유로 백엔드 몫이다.

### 올리는 메시지

봇은 받은 `msg` 를 아래 순서로 가공한 뒤 올린다.

1. **`msg` 안의 `@everyone` · `@here` 를 지운다.** 지운 자리에서 새로 생길 수 있으므로
   (`@every@hereone` → `@everyone`) 더 이상 남지 않을 때까지 반복한다.
2. **지운 결과가 비었거나 공백만 남으면 400** 이다. 보내지 않는다.
3. **맨 위에 발신자 줄을 붙인다** — `X-Discord-User-ID` 의 멘션 `<@id>` 다
   ([send-alert-message](send-alert-message.md#올리는-메시지) 와 같은 줄). 봇이 올리는 메시지라
   붙이지 않으면 채널에서 captain · navigator 중 누가 보냈는지 알 수 없다.
4. **`discordUserIds` 가 비어 있지 않으면 발신자 줄 아래에 멘션 줄을 붙인다** — 중복을 뺀 뒤 요청 순서대로
   `<@id>` 를 공백 하나로 잇는다. 빈 배열이면 멘션 줄 없이 발신자 줄과 `msg` 만 올린다.

```
발신: <@198237461928374612>
<@327394882193883136> <@412938471293847123>
이번 주 모임은 목요일 저녁 9시로 옮깁니다.
```

**길이 상한** — 발신자 줄 · 멘션 줄 · `msg` 를 줄바꿈으로 이은 전체가 Discord 메시지 한도 **2000자**를 넘으면
**400** 이다. 멘션 하나가 최대 23자(`<@` + 20자리 + `>`)라, 발신자 줄(최대 27자)과 멘션 40명(최대 959자)을 채운
최악의 경우에도 `msg` 에 **1012자**는 남는다. 멘션이 적을수록 더 쓸 수 있다.
`msg` 는 **가공 전** 값으로 잰다. 잘라서 보내지 않는다 — 뒷부분이 조용히 사라진다.

**전송은 `AllowedMentions(everyone=False, roles=False, users=[discordUserIds 의 유저들])` 로 한다** —
**요청에 넣은 유저만** 알림을 울린다.

- 발신자 줄의 `<@id>` 는 이름으로 보이기만 하고 발신자에게 알림이 가지 않는다 (발신자를 `discordUserIds` 에도 넣었으면 울린다).
- `msg` 안에 직접 적은 `<@id>` · 역할 멘션은 글자로만 보이고 알림은 없다. 알림을 울리려면 `discordUserIds` 에 넣어야 한다.
- 1번에서 놓친 `@everyone` · `@here` 가 있더라도 여기서 한 번 더 막힌다. 1번은 **채널에 보이는
  글자를 지우는 것**, 이건 **알림을 막는 것**이라 둘 다 한다.
- 유저 멘션에는 봇의 `Mention Everyone` 권한이 필요 없다.

발신자 줄과 멘션 줄에는 **ID 까지만** 넣는다 — 닉네임·이메일 같은 개인정보를 메시지 본문에 풀어 쓰지 않는다
([common-header.md](common-header.md#x-discord-user-id) 와 같은 규칙). 이름은 Discord 가 멘션을 렌더링하며 보여준다.

**멘션 대상이 그 채널을 볼 수 있는지는 확인하지 않는다.** 스터디 역할을 배정받기 전인 유저도 멘션할 수 있게 둔다 —
볼 수 없는 유저는 알림을 받지 못할 뿐 요청은 실패하지 않는다.

## 성공 응답

**204 No Content** — 바디가 없다.

**204 는 "그 채널에 이 메시지가 [가공된 모양](#올리는-메시지)으로 올라가 있다" 는 뜻이다.**
멘션한 유저 전부에게 알림이 실제로 갔다는 보장은 아니다 — 그 유저가 채널을 볼 수 없거나 알림을 꺼 두었으면
Discord 는 에러 없이 알림만 건너뛴다 ([위](#올리는-메시지) 참고).
`msg` 에서 `@everyone` · `@here` 를 지웠더라도 204 다.

생성된 **메시지 ID 는 응답에 넣지 않는다.** 호출자가 메시지를 수정·삭제할 일이 생기면 그때 추가한다.

## 실패 응답

에러 바디는 현재 FastAPI 기본형 `{"detail": "..."}` 이다
(BE 의 `{errorCode, errorMessage}` 와 다르다 — [미정 사항](#미정-사항) 참고).
같은 상태 코드가 여러 원인에 쓰이므로 **`detail` 로 구분한다.**

### 공통 헤더에서 나는 것

| 상태 | 언제 |
|------|------|
| **400** | `X-Discord-User-ID` 가 없거나 snowflake 형식이 아님 — 이 엔드포인트는 역할 확인 때문에 필수다 |
| **400** | `Idempotency-Key` 없음 |
| **401** | `X-API-Key` 없음 또는 불일치 |
| **403** | 요청자에게 captain 역할도 navigator 역할도 없음 |
| **404** | `X-Discord-User-ID` 가 그 길드의 멤버가 아님 |

### 이 엔드포인트에서 나는 것

| 상태 | 언제 | 원인 |
|------|------|------|
| **400** | `discordChannelId` · `discordStudyId` · `discordUserIds` 의 원소가 snowflake 형식이 아님 | 요청자 잘못. 그대로 재시도해도 실패한다 |
| **400** | `discordStudyId` · `msg` · `discordUserIds` 누락, 또는 타입이 틀림 (`discordUserIds` 가 배열이 아님 등) | 위와 같음 |
| **400** | `msg` 가 빈 문자열이거나 공백만 있음 | 위와 같음. 빈 메시지로 멘션만 울리게 두지 않는다 |
| **400** | `@everyone` · `@here` 를 지우고 나니 비었거나 공백만 남음 | 위와 같음 |
| **400** | 발신자 줄 · 멘션 줄과 합친 길이가 2000자 초과 | 위와 같음. 멘션을 줄이거나 `msg` 를 나눠 보낸다 |
| **400** | `discordUserIds` 가 중복을 뺀 뒤 40명 초과 | 위와 같음. 잘라서 앞의 40명만 멘션하지 않는다 — 누가 빠졌는지 호출자가 알 수 없다 |
| **400** | `discordChannelId` 채널이 텍스트 채널이 아님 (카테고리 · 음성 · 포럼 채널 등) | 요청자 잘못. 음성 채널의 텍스트 채팅에는 올리지 않는다 |
| **404** | captain 역할 또는 navigator 역할을 길드에서 찾지 못함 | 서버·길드 설정 문제(역할이 지워졌거나 잘못 지정됨). 요청자와 무관하므로 403 이 아니다. **요청자가 다른 쪽 역할을 갖고 있어도 실패한다** — 설정이 깨진 채로 권한 검사를 반쪽만 하지 않는다 ([send-alert-message](send-alert-message.md#이-엔드포인트에서-나는-것) 와 같다) |
| **404** | `discordChannelId` 채널을 봇이 찾지 못함 | 지워졌거나 없는 ID, 또는 봇에게 그 채널의 `View Channel` 권한이 없음. `POST /api/v1/ping` 의 채널 404 와 같은 결 |
| **404** | `discordStudyId` 카테고리를 봇이 찾지 못함 | 스터디 카테고리가 지워졌거나 없는 ID |
| **404** | 채널이 `discordStudyId` 카테고리 아래에 있지 않음 | 백엔드가 틀린 쌍을 보냈거나, 길드에서 채널을 다른 카테고리로 옮김. "그 스터디에 그런 채널이 없다" 로 본다 |
| **404** | `discordUserIds` 중 길드 멤버가 아닌 유저가 있음 | 탈퇴했거나 아직 입장 전. 길드에 없는 유저의 멘션은 알림 없이 깨진 글자로 남는다. **보내지 않는다** |
| **502** | Discord 가 전송을 거부 | 봇 권한 부족(그 채널의 `Send Messages`), 그 밖의 Discord 5xx |
| **503** | 봇 비활성 또는 아직 미연결 | `DISCORD_TOKEN` 미설정, 또는 기동 직후 `is_ready()` 가 아직 False |

503 · Discord 5xx 502 는 **재시도 가능**하다. 400 · 401 · 403 은 조건이 바뀌기 전에는 재시도해도 같다.
멤버 404 는 그 유저가 길드에 들어오면 통한다. 채널 · 카테고리 404 는 백엔드가 가진 ID 가 길드 상태와 어긋난 것이라
재시도로는 풀리지 않는다 — 백엔드 데이터나 길드 채널 구성을 고쳐야 한다.
역할 404 와 권한 502 는 호출자가 고칠 수 없다 — 길드나 서버 설정을 고쳐야 풀린다.

> **권한 부족 502 는 채널마다 다르다.** alert · announcement 처럼 채널이 고정이 아니라서, 봇에게
> `Send Messages` 권한이 없는 **그 채널로 가는 요청만** 실패한다. 스터디 카테고리의 권한 설정이 봇 역할을
> 막고 있는지 확인한다. 로그에는 권한 문제임과 `discordChannelId` · `discordStudyId` 를 남긴다.

> **429 는 밖으로 나가지 않는다.** discord.py 가 레이트 리밋을 내부에서 기다렸다가 재시도하므로,
> 증상은 429 응답이 아니라 **응답이 느려지는 것**으로 나타난다
> ([create-study](create-study.md#이-엔드포인트에서-나는-것) 와 같다).

## 중복 전송과 재시도

Discord 호출은 **한 번**(메시지 전송)뿐이라 부분 적용 상태는 없다. 문제는 **중복**이다 —
메시지 전송은 멱등이 아니어서, 같은 요청을 두 번 실행하면 같은 메시지가 두 번 올라가고 멘션한 유저들에게 알림이 두 번 간다.

1. **먼저 다 확인하고, 그 다음에 보낸다** — 요청자 멤버 · 두 역할 · 채널 · 카테고리 · 채널 소속 ·
   멘션 대상 멤버를 먼저 해석하고, 하나라도 문제가 있으면 아무것도 보내지 않고 실패한다.
2. **서버는 중복 요청을 막지 않는다.** `Idempotency-Key` 는 [로그 추적용](common-header.md#idempotency-key)이라,
   같은 키로 다시 와도 **다시 실행**한다.
3. **응답을 못 받은 호출자가 재시도하면 메시지가 한 번 더 올라갈 수 있다.** 네트워크가 끊겼을 뿐 메시지는
   이미 올라갔을 수 있다. 재시도할 때는 같은 키를 보내 로그에서 두 시도를 묶는다.

> **중복은 받아들인다.** 타임아웃 뒤 재시도라는 드문 경우에만 생기고, 알림이 한 번 더 울리는 정도라
> 치명적이지 않다. 중복 메시지는 captain 이 Discord 에서 직접 지운다.

## 경로 충돌

`/channels/{discordChannelId}/msg` 는 [`send-alert-message`](send-alert-message.md) 의 `/channels/alert/msg`,
[`send-announcement-message`](send-announcement-message.md) 의 `/channels/announcement/msg` 와 **모양이 겹친다.**
FastAPI 는 라우트를 등록 순서대로 매칭하므로, 동적 경로가 먼저 등록되면 `alert` · `announcement` 가
`discordChannelId` 로 잡혀 snowflake 형식 **400** 이 난다. **고정 경로를 동적 경로보다 먼저 등록한다** —
[assign-navigator-role](assign-navigator-role.md#경로-충돌) 과 같은 규칙이고, 테스트로 이 순서를 고정한다.

## 미정 사항

정해야 이 계약이 확정되는 것들.

- **발신자 줄 문구** — [send-alert-message](send-alert-message.md#미정-사항) 와 같은 결정을 따른다.
- **에러 바디 모양** — 여기는 FastAPI 의 `{"detail": ...}`, 백엔드는 `{errorCode, errorMessage}` 다.
  맞출지 말지는 별도 결정 사항.
