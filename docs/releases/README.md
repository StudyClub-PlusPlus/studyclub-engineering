# releases — 월별 업데이트 내역

**사용자 입장에서 무엇이 달라졌나**를 그달 단위로, 화면과 함께. 커밋 목록·내부 리팩터는 쓰지 않는다.
월말에 에이전트가 그달 머지 PR · PR 「화면 변경 근거」 · `specs/` 변경을 읽어 초안 PR 을 열고, 리드가 확인한 뒤 머지한다.

## 자리

```text
releases/<YYYY-MM>/
  README.md          그달 업데이트 내역
  shots/<기능>.webp   1200px · 장당 ~100KB · 한 달 10장 안쪽
```

## 화면 규칙

- **stage 우선.** prod 는 로그인 없이 누구나 보는 공개 화면만, **prod 백오피스는 찍지 않는다**
- 찍기 직전 개인정보(이메일·전화·실명·주소) 마스킹. 회원 목록·문의 본문·로그인 IP·OTP 화면은 뺀다
- 이미지 아래 라벨 — `stage 실제` / `prod 공개 화면` / `기획 화면` + 촬영일

## 양식 — `<YYYY-MM>/README.md`

```markdown
---
month: YYYY-MM
basis: 머지 PR N · specs 변경 N · 촬영 YYYY-MM-DD
drafted_by: agent · reviewed_by: (리드)
---
# YYYY년 M월 업데이트

| 영역 | 지난달 말 | 이번 달 말 | PR |
|---|---|---|---|
| 로그인 유지 | 7일마다 강제 로그아웃 | 30일 안에 오면 계속 로그인 | #NNN |

## <기능>
![<기능 설명>](shots/<기능>.webp)   *stage 실제 · MM-DD*
사용자가 무엇을 할 수 있게 됐나 한 단락. 파일명·함수명 없이.
```
