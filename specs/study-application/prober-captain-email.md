# 담당 캡틴 신청 메일 검증 케이스

테스트용 계정과 스터디에서만 확인한다. 실제 외부 메일은 stage 테스트 수신함으로 제한한다. 자동화 테스트는 메일·운영 웹훅을 모두 가짜 전송기로 대체한다.

| 케이스 | 조작 | 기대 결과 |
|---|---|---|
| 기본 | 담당 캡틴과 다른 회원이 신청 | 신청·명부 저장, 담당 캡틴에게 PENDING 예약. 폴링 후 SENT. 신청자 개인정보는 메일에 없음 |
| 현재 담당자 | 등록자와 담당 캡틴이 다른 스터디에 신청 | 등록자가 아닌 현재 담당 캡틴만 수신 |
| 본인 신청 | 담당 캡틴이 자신의 스터디에 신청 | 신청 성공. 메일·누락 경고 없음 |
| 중복 요청 | 같은 회원이 같은 스터디에 두 번 신청 | 두 번째 409. 예약 추가 없음 |
| 담당자 없음 | 담당자 null / 탈퇴 후 신청 | 신청 성공. 예약 없음. OWNER_MISSING 로그·WARN |
| 잘못된 담당자 | 없는 계정 ID / ADMIN이 아닌 계정 | 신청 성공. OWNER_ACCOUNT_NOT_FOUND / OWNER_NOT_ADMIN 로그·WARN |
| 양식 없음 | 해당 조건 템플릿 없이 신청 | 신청 성공. TEMPLATE_MISSING 로그·WARN. 양식을 복구해도 자동 소급 발송 없음 |
| 반복 누락 | 같은 스터디·사유로 10분 안에 세 건 | 개별 로그 세 건. 첫 WARN 1건, 10분 이후 요약 2건. 다른 스터디·사유는 독립 |
| 저장 실패 | 예약 저장 실패를 주입 | 신청서·명부·예약 모두 롤백. 커밋 후 누락 경고 없음 |
| 전송 실패 | 가짜 전송기가 실패하도록 설정 | 신청 유지, FAILED 기록, 담당자가 그대로면 같은 행 재발송 가능 |
| 담당자 변경 | FAILED 이후 담당 캡틴 변경 | 목록 canResend=false. 직접 재발송해도 STATE_CHANGED |
| 동시 변경 | 신청의 예약 직전에 멈추고 담당자 변경 | 변경이 기다림. 앞 신청은 옛 담당자, 변경 후 신청은 새 담당자 |
| 동시 탈퇴 | 신청의 예약 직전에 멈추고 캡틴 탈퇴 | 탈퇴가 기다린 뒤 새 예약까지 비식별화·PENDING 취소. 탈퇴가 먼저면 예약 없음 |
| 재발송 중 변경 | 재발송이 스터디 잠금을 얻기 전/후 담당자 변경 | 변경이 먼저면 제외. 재발송이 먼저면 한 번 접수 후 변경. 서로 교착 없음 |
| 링크 | 메일의 신청자 확인 버튼, 로그아웃 상태 포함 | 같은 환경 백오피스의 해당 스터디 신청자 탭. 로그인 후 원래 링크로 복귀 |
| 템플릿 관리 | 새 조건 추가·수정·삭제, 미리보기 | 이름·변수 안내 표시. 미리보기 변수는 원문 유지. 마지막 양식 삭제는 신청이 계속 접수됨을 안내 |
| 시드 | V68 두 번 적용 / 기존 운영 양식 존재 | 같은 조건 중복 생성·기존 문구 변경 없음 |

자동화 근거: StudyApplicationEmailIntegrationTest, StudyApplicationMailAlertsTest, StudyApplicationLinkTest, templates.behavior.test.tsx. 동시성은 H2뿐 아니라 MySQL에서 같은 테스트로 확인한다.
