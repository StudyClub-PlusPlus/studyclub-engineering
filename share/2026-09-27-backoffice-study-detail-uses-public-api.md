# 백오피스 스터디 상세가 "손님용 창구"를 빌려 쓰고 있다 — 한쪽을 고치면 다른 쪽이 막힌다

## 미리 알아야 할 것

처음 보는 단어부터 풉니다.

| 단어 | 뜻 |
|---|---|
| **API (창구)** | 화면이 서버에게 "이 스터디 정보 주세요" 하고 말을 거는 곳 |
| **공개용 상세 창구** | `GET /api/studies/{번호}`. **누구나**(로그인 안 한 사람도) 부를 수 있다. 사용자 사이트의 스터디 상세 페이지가 쓴다 |
| **관리자용 창구** | `/api/admin/...` 로 시작하는 창구. **캡틴만** 들어간다 ([백오피스 API 는 `/api/admin`](2026-09-24-admin-api-path.md)) |
| **DRAFT (작성 중)** | 스터디를 등록하면 처음에 이 상태다. **아직 공개 전**이라 사용자 사이트에 보이면 안 된다. 운영자가 "모집 시작"을 눌러야 공개된다 |
| **404** | 서버가 "그런 거 없어요"라고 답하는 것. 화면에는 "찾을 수 없음"이 뜬다 |

## 한 줄 요약

**백오피스의 스터디 상세 화면이 관리자용 창구가 아니라 공개용 창구로 스터디를 불러온다.**
그 공개용 창구에는 **"작성 중 스터디를 막는 규칙"이 빠져 있다.** 그래서 지금은 두 가지가 동시에 참이다.

1. **지금 뚫려 있는 것** — 일반 사용자도 번호만 알면 **공개 전 스터디를 볼 수 있다**
2. **고치면 생기는 것** — 이 구멍을 막는 순간, **백오피스에서도 공개 전 스터디가 안 열린다**

1번을 막으려면 **2번이 먼저 해결돼 있어야** 한다. 그 순서가 이 문서의 요점이다.

## 비유 — 매장 정문과 직원 출입문

옷 가게를 생각해 봅시다.

- **정문** — 손님이 드나든다. 진열된 옷만 보여야 한다
- **창고** — 아직 진열 전인 신상품(= 작성 중 스터디)이 있다. 직원이 가격표를 붙이고 다듬는 곳

그런데 이 가게는 **직원도 정문으로 드나들고 있습니다.** 직원 출입문이 아직 없어서요.

그리고 정문에 **"창고 물건은 손님에게 보여 주지 말 것"** 규칙이 빠져 있습니다.
그래서 지금은 손님이 창고 물건 번호만 알면 **신상품을 미리 볼 수 있습니다.** (1번 구멍)

누군가 이걸 발견하고 정문에 **"창고 물건 출입 금지"** 팻말을 붙입니다. 옳은 조치입니다.
그런데 직원도 정문으로 다니니 **직원까지 창고 물건을 못 만지게 됩니다.** (2번 문제)
신상품에 가격표를 붙일 사람이 없어집니다.

**그래서 팻말을 붙이기 전에 직원 출입문(관리자용 창구)부터 내야 합니다.**

## 실제로 어떻게 벌어지나 — 순서대로

**지금**

1. 캡틴이 백오피스에서 스터디를 등록한다 → 상태는 `DRAFT`(작성 중)
2. 캡틴이 목록에서 그 스터디를 눌러 정보 탭을 연다 → **열린다** ✅
3. 그런데 일반 사용자가 주소창에 `/studies/{그 번호}` 를 치면 → **이것도 열린다** ⚠️ (공개 전인데 보임)

**누군가 3번을 고친 뒤**

1. 공개용 창구에 "DRAFT 면 404" 규칙을 넣는다 (스펙에 원래 그렇게 쓰여 있다)
2. 일반 사용자가 공개 전 스터디를 열면 → 404 ✅ (의도대로)
3. 캡틴이 백오피스에서 공개 전 스터디를 열면 → **404 — "스터디를 찾을 수 없습니다"** ❌
4. 캡틴은 공개 전에 내용을 다듬어야 하는데, 바로 그 스터디의 정보 탭을 못 연다

3번을 고친 사람은 **사용자 사이트만 보고 고쳤기 때문에** 백오피스가 같은 창구를 쓴다는 걸 모를 가능성이 큽니다.
테스트도 사용자 사이트 기준으로 통과하니, 캡틴이 직접 눌러 보기 전까지 아무도 모릅니다.

## 왜 이렇게 됐나

- 백오피스 정보 탭을 이번에 실제 서버와 연결했습니다
  ([`specs/study/spec.md`](../specs/study/spec.md) 「스터디 상세 조회 › 프론트엔드 사용처」)
- 관리자용 상세 창구(`GET /api/admin/studies/{번호}`)가 아직 없어서, **이미 있던 공개용 창구를 빌려 썼습니다**
- 공개용 창구가 작성 중 스터디를 막지 않는 건 이번 작업 전부터 있던 문제입니다.
  코드는 `IS_HIDDEN`(숨김 표시)만 보고 막는데, 등록할 때 이 값이 `false` 로 들어가서 **작성 중인데도 숨김은 아닌** 상태가 됩니다

## 물어볼 것 — 백엔드

**관리자용 상세 창구 `GET /api/admin/studies/{번호}` 를 언제 만들까요?**

만들 것 자체는 작습니다.

- 캡틴만 들어온다 (`StudyCaptainGuard.assertCaptain`)
- DRAFT 도 보여 준다
- 응답 모양은 지금 공개용 상세와 같게 시작한다 — 백오피스 화면은 부르는 주소 한 줄만 바꾸면 된다
  (`frontend/apps/back-office-front/src/features/studies/queries.ts` 의 `useStudyDetail`)
