# 구글 시트 출석부를 웹 「스터디 일정」으로 옮긴다 — 참가자 모두 보고, 발표자는 선착순, 킥오프는 0회차

## 미리 알아야 할 것

| 단어 | 뜻 |
|---|---|
| **구글 시트 출석부** | 지금 스터디마다 쓰는 공유 시트. 스터디 시간 · 네비게이터 · 일정표(주차·일자·제목·발표자1·2) · 출석 체크 · 스터디 규칙이 한 장에 있다 |
| **캡틴 / 네비게이터 / 크루** | 캡틴 = 사이트 운영자(ADMIN). 네비게이터 = 그 분반을 이끄는 사람(LEADER). 크루 = 일반 참가자 |
| **분반** | 한 스터디 안의 시간대별 반 (수요일반, 미주반). 일정과 출석은 분반에 붙는다 |
| **킥오프** | 스터디 첫 모임. 규칙 · 일정 · 발표자를 여기서 정한다. 시트에는 「0회차」로 적었다 |
| **발표자1 · 발표자2** | 그 회차의 발표 담당. 1이 메인, 2가 보충 |

화면 기획은 [회차 등록 PRD](../planning/stories/navigator-register-sessions/PRD.md), 서버 계약은 [회차 스펙](../specs/study-meeting/spec.md) 결정 9~12 에 있다.
playground 에서 「내 스터디 → 스터디 일정」 으로 직접 볼 수 있다.

## 한 줄 요약

내 스터디 카드의 **「스터디 일정」** 버튼은 참가자 모두에게 보인다. 캡틴·네비게이터는 표에서 바로 고치고, 크루는 보면서 **빈 발표자 칸에 자기 이름만** 넣을 수 있다. 킥오프는 0회차로 두고 출석률에서 뺀다.

## 비유 — 교실 뒤 게시판

시트는 "누구나 고칠 수 있는 공책"이었다. 웹은 **교실 뒤 게시판**이다. 모두가 본다. 게시판을 고치는 건 반장(네비게이터)과 선생님(캡틴)이다. 다만 발표 신청란은 빈칸에 학생이 자기 이름을 적을 수 있다 — 먼저 적은 사람이 임자다.

## 왜 — 시트에서 불편했던 것

- 누구나 아무 칸이나 고칠 수 있어, 실수로 지워도 누가 했는지 모른다
- 발표자 칸과 「발표 여부」 칸이 따로 있어 둘이 어긋났다
- 킥오프를 0회차로 적다 보니 출석률 계산에 섞였다

## 정해진 것

1. **버튼은 「스터디 일정」, 참가자 누구에게나 보인다.** 캡틴도 백오피스가 아니라 같은 화면으로 간다
2. **고치기는 캡틴·네비게이터만.** 일정 추가·수정·삭제, 출석 체크, 규칙 수정
3. **크루는 본다.** 일정 · 규칙 · 분반 전원의 출석부를 본다. 고치지는 못한다
4. **발표자는 드롭다운으로 고른다.** 캡틴·네비게이터는 누구든 넣고 뺀다. 크루는 **빈 칸에 자기만** 넣고 자기만 뺀다(선착순, 한 회차에 한 칸)
5. **발표 여부는 따로 적지 않는다.** 출석부 칸의 마이크 표시와 「발표 횟수」 열은 일정의 발표자에서 계산한다
6. **표에서 바로 고친다.** 칸을 그 자리에서 고치고, 여러 줄을 고친 뒤 「저장」 한 번
7. **일자와 시각을 나눠 보인다.** KST · PDT 탭에 따라 바뀌고, 고른 시간대 그대로 고친다(저장은 UTC). 상태 열은 없다 — 지난 회차는 흐린 글자
8. **킥오프 = 0회차.** 분반마다 하나, 지울 수 없음, 발표자 없음, **출석은 찍고 출석률에선 뺀다**
9. **스터디 규칙은 일정 탭 맨 위 카드.** 따로 탭을 두지 않는다 — 일정 보러 온 사람이 규칙도 본다. 캡틴·네비게이터에게는 늘 열려 있는 글 상자
10. **스터디 시간과 네비게이터는 백오피스에서 캡틴이 고친다.** 이 화면은 보여 주기만 한다

## 남은 질문 (세은님)

- **이미 운영 중인 분반에도 킥오프 회차를 만들까요?** 시트에는 0회차가 있지만 DB 에는 없다. 지금은 새로 만드는 분반에만 만든다
- **한 사람이 맡을 발표 수에 상한을 둘까요?** 지금은 없다
- **발표자1이 빠진 날 발표자2가 대신한 것을 따로 남길까요?** 지금은 일정의 발표자를 고쳐서 남긴다
- **캡틴에게도 「담당 반에 한해」 가 걸리나요?** 지금은 캡틴이 모든 분반을 고칠 수 있다 (10-02 기록에서 이어지는 질문)

## 영향 — 누가 무엇을 해야 하나

- **백엔드**: 컬럼 4개(`STUDY_MEETING.MEETING_TYPE` · `PRESENTER1_PARTICIPANT_ID` · `PRESENTER2_PARTICIPANT_ID`, `STUDY_GROUP.RULES` 500자)를 마이그레이션으로 더한다. 목록 GET 권한을 「분반 참여자」로 넓히고, 발표 신청 API 와 규칙 저장 API 를 새로 만든다. 출석률 산식에서 킥오프를 뺀다. 반 만들기에서 킥오프를 함께 만든다. 자세한 건 [회차 스펙 구현 메모](../specs/study-meeting/spec.md#구현-메모)
- **프론트**: core-front 스터디 일정 화면을 playground 대로 만든다. 출석부 격자는 백오피스와 같은 컴포넌트에 `readOnly` · 발표 표시 · 킥오프 제외 옵션이 생겼다
- **디자인**: playground 의 표 편집 · 발표 신청 · 규칙 카드 모양을 확인해 주세요
