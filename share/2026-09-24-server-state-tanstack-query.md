# 화면이 서버 데이터를 가져오는 방법을 하나로 정한다

## 미리 알아야 할 것

| 단어 | 뜻 |
|---|---|
| **서버 상태** | 우리 서버(DB)에 있는 데이터를 화면이 잠깐 빌려온 것. 스터디 목록, 유저 목록 같은 것 |
| **클라이언트 상태** | 화면에만 있는 것. 지금 연 탭, 입력 중인 글자 |
| **캐시** | 한 번 가져온 것을 잠깐 들고 있다가 다시 쓰는 것. 화면을 옮겼다 돌아올 때 다시 안 부르려고 |
| **TanStack Query** | 그 캐시를 대신 관리해 주는 라이브러리. 예전 이름이 React Query |
| **BFF** | 우리 프론트 서버 안의 중계 창구(`/api/...`). 브라우저 대신 백엔드를 불러준다 |

한 가지만 더. 우리 로그인 토큰은 **httpOnly 쿠키**에 있습니다. 이건 *"브라우저 자바스크립트가
읽을 수 없는 쿠키"* 라는 뜻입니다. 그래서 브라우저가 백엔드를 직접 부르면 **"나 누구요"를 증명할
방법이 없습니다.** BFF 가 그 증명을 대신 붙여 줍니다.

## 한 줄 요약

**서버에서 데이터를 가져오는 일은 전부 TanStack Query(`useQuery`)로 한다.**
그리고 그 코드는 `lib/api/` 같은 공용 서랍이 아니라 **그 기능 폴더 안에** 둔다.

## 왜 — 지금 뭐가 문제였나

세 가지였습니다.

**하나. 라이브러리를 깔아놓고 안 썼습니다.** `@tanstack/react-query` 가 두 앱의 `package.json` 에
들어 있는데 `useQuery` 를 부르는 곳이 **한 군데도 없었습니다.** 화면마다 `useEffect` 로 직접
불러오고, 로딩·에러 상태를 손으로 만들고 있었습니다.

**둘. 같은 코드를 화면마다 다시 썼습니다.** 불러오기·로딩 표시·에러 문구·다시 부르기 —
화면이 늘어날 때마다 이 네 덩어리가 복사됐습니다. 한 군데서 실수하면 그 화면만 조용히 다르게 굽니다.

**셋. 규약이 "공용 서랍에 모으라"고 하고 있었습니다.** 기존 가이드는 API 호출을 `lib/api/` 에
모으라고 했는데, 이러면 **스터디 기능 하나를 고치는 데 폴더 네 개를 열어야** 합니다.

## 비유 — 부엌 정리

칼·도마·냄비를 종류별로 **다른 방**에 보관한다고 해봅시다. 칼방, 도마방, 냄비방.
"라면 하나 끓이자"에 방 세 개를 돕니다.

정리를 **요리별로** 바꾸면 — 라면 칸에 라면 냄비·젓가락·계량컵이 같이 있습니다. 라면을 안 하게 되면
그 칸을 통째로 비우면 됩니다. 우리가 고른 게 이겁니다.

```
❌ 종류별 서랍                       ✅ 기능별 칸
src/lib/api/studies.ts              src/features/studies/
src/models/Study.ts                   ├── types.ts      (타입·변환)
src/components/StudiesTable.tsx       ├── queries.ts    (키·호출·훅)
src/app/studies/page.tsx              └── StudiesTable.tsx
```

## 정해진 것

1. **조회는 `useQuery`** — `useEffect + fetch` 로 직접 상태를 만들지 않는다
2. **기능 폴더에 모은다** — `src/features/<기능>/{types.ts, queries.ts, 전용컴포넌트}`.
   판정 한 문장: *"이 기능이 없어지면 같이 지워지는가."*
3. **페이지는 조립만** — `app/.../page.tsx` 에서 `fetch` 를 직접 쓰지 않는다
4. **QueryClient 는 한 곳에서** — 서버는 요청마다 새로, 브라우저는 하나를 재사용.
   서버에서 하나를 공유하면 **A 가 본 데이터가 B 에게 보인다**
5. **401(로그인 끊김)은 화면마다 처리하지 않는다** — 전역에서 세션을 비우고 로그인으로 보낸다
6. **읽기 전용 공개 화면은 서버 컴포넌트로 충분하다** — 모든 화면에 쿼리를 깔지 않는다

기본값도 정했습니다.

| 설정 | 값 | 왜 |
|---|---|---|
| `staleTime` | 60초 | 기본값 0이면 화면을 그리자마자 또 부른다 |
| `retry` | 0 | 권한 없음(403)을 세 번 더 물어봐도 답은 같다 |
| `refetchOnWindowFocus` | false | 탭 옮길 때마다 부르면 운영 화면이 시끄럽다 |

## 무엇을 안 하기로 했나 (중요)

**남이 하니까 따라 하지 않은 것들입니다.** vcraft(사내 다른 서비스)와 공식 문서를 조사하고 골랐습니다.

| 안 한다 | 왜 |
|---|---|
| 쿼리 키를 모아두는 **전역 딕셔너리** | vcraft 는 200줄짜리를 씁니다. 도메인이 30개라 **이름이 충돌**해서 생긴 장치입니다. 우리는 기능이 몇 개뿐이라 필요 없습니다 |
| 별도 **공유 쿼리 패키지** | vcraft 에도 있지만 **정작 그쪽 백오피스는 그 패키지를 안 씁니다.** 앱이 2개면 앱 안에 두는 게 맞습니다 |
| 키 팩토리 **라이브러리 설치** | 손으로 쓴 객체 세 줄이 더 쌉니다. 외부 라이브러리 추가는 합의 사항이기도 합니다 |
| 모든 화면에 **서버 미리 불러오기(prefetch)** | 이 규모에 과합니다. 첫 화면 깜빡임이 실제로 거슬리는 화면에만 붙입니다 |
| **낙관적 업데이트**를 기본으로 | 저장이 실패하면 되돌리는 코드가 필요한데, 그게 버그의 온상입니다. 좋아요·읽음 같은 토글에만 씁니다 |

한 가지는 **조사한 두 곳이 서로 달라서** 직접 골랐습니다 — `refetchOnMount`.
vcraft 백오피스는 이걸 꺼두고 저장할 때마다 손으로 갱신을 부릅니다. 우리는 **켜둔 채(기본값)**
둡니다. 끄면 갱신 호출을 **한 번만 빠뜨려도 화면이 옛 데이터를 계속 보여주고**, 그게 언제
틀렸는지 아무도 모릅니다.

## 영향 — 누가 무엇을 해야 하나

| 누가 | 무엇을 |
|---|---|
| **프론트 개발자 전원** | 새 화면은 `features/<기능>/queries.ts` 에 훅을 만들고 페이지에서 그 훅을 쓴다. `useEffect + fetch` 금지 |
| **백오피스** | 이번 PR 에서 스터디·알림 템플릿·유저 3화면이 이미 전환됐다. 나머지는 손댈 때 같이 옮긴다 |
| **사용자 사이트(core-front)** | 아직 `useEffect` 다. 별도 PR 로 같은 구조로 옮긴다 |
| **리뷰어** | 페이지에서 `fetch(` 가 보이면 잡아 주세요 |

규칙 전문: [`docs/frontend-development-guide/api-integration.md`](../docs/frontend-development-guide/api-integration.md)

## 덤으로 고친 것

기존 가이드의 예제가 응답에서 `json.data` 를 꺼내 쓰고 있었습니다. **우리 백엔드는 그런 껍데기를
씌우지 않습니다** — 그대로 따라 쓰면 전부 `undefined` 가 됩니다. 문서를 고쳤습니다.
